## 1. 目标与边界

### 1.1 本轮目标

保留现有 Qt Widgets、QtNodes、领域模型和执行引擎，将目前偏“开发调试工具”的界面收敛为职责清楚、交互一致的视觉工作台。

本轮首先解决三件事：

1. **操作作用域清楚**：方案、流程、模块的运行入口分开；停止动作有明确目标，不受历史浏览影响。
2. **结果职责清楚**：区分图像、完整模块输出、当前检测结果和历史结果；所有联动视图都能解释数据来自哪一轮。
3. **视觉规则一致**：面板、工具栏、页签、表格、节点和空状态使用统一规范，而不是逐个控件零散美化。

本轮不以增加算法数量为目标。先用已有工具跑通“搭建—配置—执行—查看—修改—重跑—保存”的完整操作链。

### 1.2 必须保留的能力

- 已有方案、流程、Group、循环、控制连接与数据绑定模型。
- 已有执行状态、业务判定、运行身份、结果来源和配置快照契约。
- 已有保存、加载、撤销、重做、只读限制及关闭收尾逻辑。
- 已有图像预览、历史跟随与锁定、诊断定位、独立模块配置窗口。
- 已有浅色、深色和跟随系统的外观能力；优先建立一套视觉基准，但不得破坏其他模式。

### 1.3 本轮禁止顺手扩大的范围

- 不因为 UI 改造重写执行引擎、替换 Qt 技术栈或更换节点编辑库。
- 不将“控制连接”“数据绑定”“Group 包含关系”合并成一种连线。
- 不为模仿参考软件外观而改变已有执行语义。
- 不一次补齐海康全部算法、设备驱动或节点参数。
- 不在基础工作台尚未稳定前开发完整拖拽式运行界面设计器。
- 不复制海康的商标、图标资源或截图作为 VisionPro 的产品资源。
- 不用无实际后端支持的按钮、假数据或延时动画冒充已实现能力。

### 1.4 设计依据与证据边界

本文整理自上一轮静态代码评审及工作台优化方案。**文件名和现状描述是实施线索，不是对执行时仓库状态的保证。**

Codex 开始实施时，应按以下优先级核实：

1. 当前工作区及适用范围内的 `AGENTS.md`。
2. 当前分支代码、测试、构建配置与项目文档。
3. 用户指定的海康在线手册中能够实际核实的正文与截图。
4. 本文中的推荐布局和交互规则。

参考入口：

- 项目分支：<https://github.com/nooblegendliu/VisionPro/tree/codex/solution-orchestration>
- 用户指定手册：<https://pinfo.hikrobotics.com/hkws/unzip/20260602153721_99404_doc/>
- 仓库对齐计划：`docs/visionmaster-alignment-plan.md`。
- 仓库架构与开发说明：`docs/architecture.md`、`docs/data-model.md`、`docs/development.md`。

注意：上一轮没有完整取得指定手册的全部正文，也没有运行当前 Windows 程序做像素级检查。本文的布局比例、组件尺寸、上下文划分属于 **VisionPro 的设计建议**，不应标成“海康原版规范”。如旧版手册与指定版本冲突，以已核实的指定版本为准；未核实处明确记录，不补造依据。

## 2. Codex 执行规则

### 2.1 任务选择与阶段边界

- 每次只执行用户明确指定的阶段或任务编号。
- 用户只说“按本文开始”而未指定编号时，默认执行 **UI0**，不要直接横跨所有阶段。
- 用户明确要求连续执行多个阶段时，按依赖顺序推进；前一阶段硬门槛失败，不得把后一阶段标成完成。
- 一个阶段内优先按任务编号做小范围修改，避免一次重写所有 UI 文件。
- 新类、新文件名称均为建议；已有合适抽象必须优先复用，不为对齐本文名称制造重复架构。
- 完成一个阶段后提交阶段报告，不自动宣称后续阶段已完成。

### 2.2 工作区保护

修改前查看 `git status --short`，保留用户已有改动。不得擅自执行清理工作区、覆盖用户修改、切换分支、强制重置、推送远端等操作。

目标分支与当前分支不一致时，先确认实际工作区内容并在报告中说明；不要自动切换导致已有改动丢失。存在直接冲突的文件时，保留现场并说明阻塞点，其余独立任务可以继续完成。

### 2.3 实施原则

- 先阅读，再修改；先记录现状，再宣布缺口。
- 后端已有能力优先接线，不重复实现。
- 命令准入、取消和结果有效性沿用控制器及结果接口的判断。界面只处理用户可见且需要不同反馈的状态。
- 后端缺少能力时，明确禁用、只读或移至后续任务，不在 UI 层模拟调度。
- 运行状态来自实际控制器或运行句柄，不通过按钮是否按下推测。
- UI 状态不反向污染方案数据；节点位置等已有持久化布局字段继续遵守现有方案格式。
- 对外使用中文显示名；内部 ID、类型 ID、运行 ID 保留在详情和复制入口，不丢弃追溯能力。
- 不因视觉改造删除键盘操作、焦点状态、可访问名称或已有快捷键。
- 不以“测试无法运行”为理由伪造通过结果；明确区分通过、失败、未执行和环境阻塞。

### 2.4 每个任务的标准完成定义

任务完成必须同时满足：

- 目标行为已经实现，而不只是搭出空面板。
- 修改范围与本文该任务一致，未无说明扩大到引擎或方案格式。
- 原有关键行为仍可用，新增行为有对应自动化测试或可复现的手工步骤。
- 用户可见文字、禁用原因、空状态和错误状态完整。
- 新增编译单元已接入实际构建目标，适用的平台配置不被破坏。
- 阶段报告列出真实命令、结果、限制和未完成事项。

## 4. 目标工作台及区域职责

以下结构是 VisionPro 推荐布局，不是海康截图的逐像素复刻。

```text
主窗口
├─ 菜单栏：文件、编辑、方案/流程、运行、视图、帮助
├─ 主工具栏：文件操作｜方案资源｜方案运行与停止｜视图切换
├─ 中央工作区
│  ├─ 工具箱：分类轨道＋按需展开的工具抽屉
│  ├─ 编辑区域
│  │  ├─ 页面：方案总览｜流程 A｜流程 B
│  │  ├─ 当前页面局部工具条
│  │  ├─ 当前流程 / Group 层级路径
│  │  ├─ 方案关系视图或流程画布
│  │  └─ 当前流程状态、耗时、缩放等局部信息
│  └─ 结果区域
│     ├─ 主视图：模块图像｜流程图像｜模块输出数据
│     ├─ 来源、轮次、跟随/锁定状态
│     ├─ 图像视口或完整输出检查器
│     └─ 下部页签：当前结果｜历史结果｜帮助
├─ 按需面板：诊断、运行轨迹、高级详情
└─ 状态栏：最近事件、活动运行状态、诊断入口

独立窗口
├─ 模块配置窗口
└─ 方案资源窗口或资源工作区页面
```

### 4.1 区域职责表

| 区域 | 应承担 | 不应承担 |
|---|---|---|
| 主工具栏 | 文件与方案级命令 | 根据历史选择隐式切换停止对象 |
| 流程局部工具条 | 当前流程运行、触发配置、布局、流程属性 | 冒充整方案命令 |
| 节点右键与配置窗口 | 模块调试、模块状态重置、输入输出查看 | 全局设备生命周期管理 |
| 工具箱 | 发现、搜索、添加工具 | 用大量空类别或模拟工具占据默认视野 |
| 方案总览 | 展示流程入口、控制关系和公开数据映射 | 将控制关系与数据关系画成无法区分的一种线 |
| 图像主视图 | 明确来源的图像、叠加、缩放与取样 | 通过长说明文字反复改变图像视口高度 |
| 模块输出数据 | 查看全部已声明输出及有效性、来源 | 仅用前三个字段拼接摘要替代完整结果 |
| 当前结果 | 展示本次检测关注的指标、范围、判定 | 堆出所有底层字段和运行轨迹 |
| 历史结果 | 选择轮次、比较关键指标、锁定历史 | 选中一行后改变主停止按钮目标 |
| 方案资源 | 集中管理或查看相机、连接、变量、队列、触发配置 | 在每个模块里重复建立一套资源管理逻辑 |
| 日志与诊断 | 解释异常、定位对象、追溯操作 | 默认占据图像和画布的主要空间 |

### 4.2 阶段性降级规则

- `模块图像`、`流程图像`没有可用来源时，显示原因，不回退成没有标签的任意旧图。
- 某类资源没有完整编辑接口时，显示真实只读内容及限制；无内容也无支持时不要假装可添加。
- 运行视图尚未实现前，可以保留设计位置，但不得显示正常可点击且无行为的按钮。
- “帮助”优先使用已有工具描述和经核实的文档入口；不得生成看似官方的算法参数说明。

## 5. 全阶段必须遵守的交互契约

### 5.1 三种上下文必须分开

必须区分：

```text
编辑上下文：我正在编辑哪个方案、流程、Group、模块或资源？
浏览上下文：我正在查看哪个方案轮次、流程轮次、模块调用的结果？
控制上下文：这次运行、停止、取消命令将发给哪个活动执行对象？
```

示例：

```text
编辑对象：流程 A / 连通域分析
浏览对象：流程 A 的第 101 轮，已锁定历史
控制对象：当前正在执行的单次整方案运行
```

在该状态下，点击方案停止不得去取消第 101 轮，也不得因用户选择了流程 B 而改变方案级按钮的职责。

可新增轻量的工作区上下文对象，或扩展已有等价抽象。建议职责如下，名称不强制：

| 职责 | 需要表达的数据 | 限制 |
|---|---|---|
| 编辑选择 | 文档身份、流程 ID、Group 路径、实体类型和实体 ID | 不保存会因模型重建失效的裸节点指针 |
| 结果浏览 | 跟随/锁定模式、运行身份、调用身份、关联结果句柄 | 不只用“表格第几行”定位结果 |
| 图像浏览 | 模块/流程/手动预览模式、来源、浏览轮次 | 手动打开图片不隐式替换算法输入 |
| 运行控制 | 命令作用域、真实活动对象、后端能力、停止状态 | 不从编辑选择或历史列表推断运行目标 |

运行 ID、调用 ID 和配置身份优先复用现有领域类型，不再制造一套语义重复的字符串 ID。

### 5.2 上下文转换规则

| 用户或系统动作 | 必须发生的行为 |
|---|---|
| 选择另一个模块，处于跟随模式 | 在同一个明确的流程浏览轮次中更新模块图像、输出和判定；尚无结果时显示尚未运行 |
| 选择另一个模块，已锁定历史 | 保留流程轮次和所选迭代的作用域。在该作用域找到目标模块的唯一调用就显示它；本次未执行就显示缺失。如需在多个调用间选择，列出候选并等待选择。 |
| 点击某条历史记录 | 图像、完整输出、当前结果切到同一个可追溯浏览上下文 |
| 开启“跟随最新” | 解除历史锁定，统一切到最新可用且身份一致的结果 |
| 切换流程 | 恢复该流程自己的浏览状态，或按既定策略重置；不得把流程 A 的锁定记录当成流程 B 的结果 |
| 手动打开预览图 | 明确标注“手动预览”；只有显式选择绑定/导入操作才改变模块配置 |
| 参数修改但尚未重跑 | 旧结果仍可查看，但标注来自修改前配置，不宣称代表当前参数 |
| 删除当前选中模块 | 清理失效编辑选择；历史记录可按旧快照只读查看，不解引用已删除对象 |
| 新建、打开或替换方案 | 清理不属于新文档的选择、浏览与控制引用；迟到回调按文档身份拒绝 |
| 从运行 A 切换到运行 B | 不混合 A 的图像、B 的判定和当前草稿的字段值 |

### 5.3 配置版本与旧结果

已保存的方案修订号未必在每次草稿编辑时变化，因此不得只用保存修订号判断“结果是否过期”。

优先复用现有快照或草稿变更标识；确有缺口时，可增加仅属于 UI/编辑会话的变更代次或内容身份。其用途仅是比较“当前草稿”与“本次运行使用的配置”，不得为此改变持久化版本语义。

撤销回到旧内容后，只有能够证明内容一致时才显示一致；无法证明时可保守标注“结果来自此前配置”，不能伪造匹配。

### 5.4 跟随、锁定与结果生命周期

- 模块图像、输出和判定共用选中的运行与模块调用。“流程图像”也使用这一轮，其来源由流程页单独选定并显示在图像旁。
- 循环、多次调用或重试存在时，不能只使用 `NodeId` 识别一次结果；必须沿用现有作用域/调用/尝试身份。
- 锁定历史时，结果与图像引用应有明确持有策略；不能保留悬空引用。
- 历史淘汰必须遵守已有容量策略。确需保留一个锁定项时，明确上限与释放时点，不让每次点击无限增加保留量。
- 结果已被淘汰或图像无法恢复时，显示“已不可用”及原因，不偷偷改显示另一轮。
- UI 不得为了显示历史而重新执行节点或触发设备动作。

### 5.5 运行与停止作用域

| 入口 | 默认作用域 | 主要行为 |
|---|---|---|
| 顶部“运行方案” | 整方案 | 使用实际方案运行入口 |
| 顶部“停止方案”或“取消本次方案运行” | 指定的活动方案运行/运行会话 | 按后端能力执行明确的停止或取消 |
| 流程局部“运行当前流程” | 当前流程 | 使用已有单流程运行入口 |
| 流程局部“取消本次流程运行” | 当前流程独立启动的单次运行 | 只有一个可取消目标时直接取消；有多个时显式选择轮次；没有时禁用 |
| 流程局部“启动触发/停止触发” | 该流程的触发源 | 与流程执行停止语义区分 |
| 模块配置“调试本模块” | 当前配置模块 | 沿用已有隔离/活动状态调试契约 |
| 历史或轨迹中的“取消此运行” | 用户明确指定且仍可取消的运行 | 保留为高级动作，不替代主停止按钮 |

停止按钮的主点击必须直接执行明确动作，不能只弹菜单。

若使用分裂按钮，主区域执行默认动作，下拉区域提供其他受支持的停止策略。可采用 `MenuButtonPopup` 或等价实现，但不得仅更改按钮样式而没有真实的默认动作。

默认策略须先核实能力：

- 单次运行：通常为取消该次运行，按钮文字必须与实际语义一致。
- 连续/触发运行：有排空能力时，默认停止接收新任务并等待在途完成；下拉可提供取消在途。
- 方案级尚不支持某种连续或排空策略时，不得借用流程级命令冒充；明确禁用或只暴露已支持的方案取消。
- 同作用域存在多个活动对象时，使用显式活动目标选择，不静默选择历史项或任意最后一项。

只有独立流程在运行时，顶栏方案停止保持禁用，用户从流程工具条取消单次运行或停止触发。`Shift+F5` 保留“取消工作台所示轮次”的语义，仅在该轮仍可取消时生效。运行详情面板另有自己的“取消此运行”。

方案取消分三个可观察的时刻。请求已受理时显示“已请求取消”，停用该次取消动作。方案报告返回时显示报告终态，若其中仍有子流程尚未退出，同时显示“正在清理”。所涉子流程均已 `quiescent` 后结束清理提示，并按控制器现有准入条件恢复运行入口。状态取自控制器和子流程句柄。

### 5.6 四种结果职责

| 视图 | 必须包含 | 无数据时 |
|---|---|---|
| 模块图像/流程图像 | 图像来源、轮次、叠加来源、浏览模式 | 区分尚未运行、无图像输出、输出无效、已淘汰 |
| 模块输出数据 | 全部声明输出、类型、值/缺值原因、单位、来源 | 无效输出仍保留字段及诊断 |
| 当前检测结果 | 当前关注指标、实测值、允许范围、业务判定 | 没有判定规则时显示未配置/不适用，不能默认 OK |
| 历史结果 | 轮次、执行状态、业务判定、关键指标、耗时 | 没有记录时给出下一步操作提示 |

执行成功不等于业务 OK。业务 NG 不等于技术异常。等待、取消、超时、跳过和禁用都应有可区分的文字或图标，不能只靠红绿颜色。

### 5.7 模块配置的提交规则

目标基线是“字段成功提交后进入方案草稿，并进入现有撤销栈”。先核实当前 Inspector 的真实提交行为，保持兼容地统一：

- 编辑中但尚未通过校验的文本不写入有效草稿。
- 同一次字段编辑合理合并撤销记录，避免每个字符制造一个大范围重建。
- 采用即时提交后，不增加没有独立语义的“应用”按钮。
- 多字段必须整体提交的专用编辑器，可以使用明确的事务式应用/取消，但必须说明作用范围，不与通用字段偷偷混用。
- 运行明确使用某一份配置快照。当前草稿与该快照不同，应显示提示。
- 独立配置窗口可以保持非模态；必须标明模块身份，且不能在用户编辑一半时因画布选择变化而悄悄替换对象。
- 若保留选择跟随行为，应先提交或明确处理当前编辑，并以一致规则切换；默认优先固定打开时的模块身份。

## 7. UI1：上下文与运行命令收敛

### UI1.1 统一编辑与结果浏览上下文

优先扩展已有选择和图像来源对象；确有必要时新增轻量协调对象，例如 `workspace_context.*`。禁止重复保存一份完整领域模型。

## 8. UI2：功能区职责与配置骨架完善

### 阶段目标

在统一上下文上完善右侧结果区、方案级入口和模块配置容器。先建立可扩展骨架，不等待全部算法节点完成。

### UI2.1 拆分完整输出、当前结果与历史

保留 `ModuleHistoryPanel` 已有的跟随/锁定能力，将“完整输出查看”和“当前业务结果”从历史摘要职责中分离。

可选新增组件名称：`module_output_panel.*`、`current_result_panel.*`。已有等价组件可直接扩展。

实施要求：

- 完整输出检查器枚举所有声明输出，显示中文名、类型、值、单位、有效性及来源。
- 对集合和结构体采用可展开、按需加载的树或等价视图；大列表不能一次生成海量单元格阻塞主线程。
- 图像类型展示尺寸、像素格式、来源与预览入口，不把图像原始字节塞进表格。
- 无效、缺失、未产出、已淘汰分别给出明确表示；存在诊断时可跳转。
- 当前结果只展示已配置或已有明确描述的业务指标与判定。
- 范围判断等已有专用显示逻辑可以迁移到 UI 呈现适配器；避免继续在通用面板堆积大量工具类型判断。
- 保留通用回退展示，尚无专用适配器的节点不能显示空白或伪造指标。
- 默认显示名称与内部端口 ID 分离，高级详情仍能复制内部 ID。
- 模块各视图使用 UI1 的同一个调用身份；切到流程图像时保留浏览轮次，并按 UI2.2 显示其来源。

主要位置：`module_history_panel.*`、`image_panel.*`、`editor_runs.cpp`、描述符的现有显示元数据。

用至少四个输出的模块核对完整字段、无效原因和业务 NG。复用 UI1.5 的两次迭代场景，锁定 A 后切换到 B，核对模块图像、完整输出和判定均取自同一轮中选定的 B 调用。

### UI2.2 建立图像模式与右侧上下分区

推荐右侧上部提供 `模块图像 / 流程图像 / 模块输出数据`，下部提供 `当前结果 / 历史结果 / 帮助`。

实施要求：

- 图像来源规则显式定义，并复用当前 `RunImageSource` 或等价机制。
- “流程图像”页提供“选择来源”，列出本流程节点声明的图像输出，以“模块名 / 输出名”显示。首版在当前文档会话内为每个流程记一个节点 ID 和输出 ID，切换模块或流程页保留选择，关闭或替换文档后清空。该选择只影响浏览，无须写入方案或 `QSettings`。
- 从当前浏览轮次的快照和结果解析所选端口。来源在循环中时沿用所选迭代的作用域，有多个候选调用时由用户选择。未选来源时提示“选择来源”；所选端口本轮跳过或未产出时保留来源名及原因，清空图像与叠加。
- 保留手动预览模式和返回运行输出入口。
- 切换上下页签不改变被浏览的轮次，不清空有效锁定。
- 帮助内容根据选中工具描述或已有文档显示；不阻塞 UI 读取网络内容。
- 不必本阶段支持多画面拼接或复杂渲染设计器。

验收时给同一流程准备两个可辨的图像输出，选定其中一个。换模块或页签仍显示所选来源；下一轮该端口跳过而另一端口有图时，显示所选来源和缺图原因。切回有图的旧轮可见原图，重开文档后提示重新选择。

### UI2.3 新增方案总览入口，第一版只读也必须真实

在流程页旁增加固定的“方案总览”入口，展示真实方案关系。

第一版必须显示：流程列表、入口标识、启用状态、方案级控制关系、公开输入输出映射，以及明确来源的运行状态。

实施要求：

- 优先读取现有方案模型，不引入第二份方案图存储。
- 数据映射和执行关系用不同的线型、标签或独立列表表达，不能靠难以辨认的颜色区分。
- 支持从总览定位到流程页；空方案给出添加流程入口。
- 已实现的连线编辑直接复用；未实现时明确为只读，不做可拖但无法保存的假编辑。
- 首版按控制器现有生命周期，只展示当前文档最近一次可用的 `SolutionRunReport`。用报告的快照和 `sequence` 标识方案轮次，通过 `report.runs` 中完整的 `RunIdentity` 定位子流程。启动下一次整方案运行后，等待它自己的报告。
- 普通流程历史仍按原容量保留。所浏览的子运行能在当前报告中精确找到时显示所属方案轮次；否则只展示该流程轮次，来源栏显示“无可用的所属方案报告”。独立运行的 A 不会被归入同名流程的方案轮次。首版直接查询现有报告，无须另存父子索引。
- 不将当前 `ControlGraphModel` 强行塞入跨流程编排职责。可以新增专用投影层，但不得复制调度逻辑。

主要位置：`editor_window.*`、已有方案模型与方案运行报告；必要时新增 `solution_overview.*`。

使用 UI0 的 A→B 样例核对入口、控制关系、公开映射，并从总览进入流程。依次执行整方案（`index=0`）、独立 A、整方案（`index=1`）。最后总览只列第二次方案的实际子运行；回看第一次 B 仍显示其输入 6 和流程轮次，注明所属方案报告不可用。独立 A 不出现在两次方案的子运行中。

### UI2.4 增加方案资源入口

建立统一“方案资源”窗口或工作区页面。分类至少规划相机、通信连接、全局变量、数据队列、触发配置。

实施要求：

- 先复用已有相机、通信、变量与队列编辑器和查询接口，不重新写驱动。
- 资源定义、运行状态和模块引用分开显示。

- 已有共享数据文本报告可以保留在高级详情；默认页改成结构化列表和详情。
- 按实际能力提供增删改、连接测试或只读查看，逐项标明限制。
- 打开资源窗口不自动连接相机、不发送 PLC 报文、不消费队列。
- 选择资源不会破坏现有模块图像的历史锁定；需要切换右侧上下文时必须有明确规则和标题。
- 资源引用有稳定身份；重命名不破坏绑定。

主要位置：`editor_runs.cpp`、`camera_editor.*`、`endpoint_editor.*` 及既有资源编辑实现；必要时新增 `solution_resources.*`。

验收：用户能从一个入口找到已有资源，识别定义值与运行值，且仅查看不会产生设备副作用。

### UI2.5 统一独立模块配置窗口骨架

保留独立配置窗口，统一身份栏、分组页签、内容区与底部调试状态。推荐骨架：

主要位置：`editor_window.cpp` 的配置窗口、`editor_inspector.*`、现有专用编辑器。

验收：打开、编辑、撤销、调试、关闭、重开同一模块行为一致；配置窗口不因画布选中另一模块而意外丢失当前编辑。

## 9. UI3：统一视觉、节点和布局

### 阶段目标

在功能职责稳定后统一视觉语言，重点解决尺寸、对齐、边界、状态和信息密度，不以渐变、大阴影或颜色数量制造“高级感”。

### UI3.1 建立设计令牌和标准组件

扩展现有 `workspace_style.*`、`workspace_appearance.*`，避免另建平行主题系统。

至少统一以下令牌：

- 颜色：窗口、表面、画布、边界、主文字、次级文字、禁用文字、品牌强调、焦点、选择、警告、执行异常、业务 OK/NG。
- 尺寸：常用间距、面板标题高度、控件高度、图标尺寸、表格行高、圆角、分割器宽度。
- 字体：正文、标题、次级说明、节点标题、数值/技术详情；使用实际可用字体与合理回退。
- 状态：默认、悬停、按下、选中、焦点、禁用、错误。

推荐初始数值如下，均为设计起点，必须按真实字体和显示缩放验证：

| 项目 | 推荐起点 | 约束 |
|---|---|---|
| 间距 | 4 / 8 / 12 / 16 个逻辑像素 | 同类布局采用相同规则 |
| 普通输入控件 | 约 28–32 个逻辑像素高 | 不截断中文、箭头和焦点边框 |
| 面板标题 | 约 30–34 个逻辑像素高 | 同层级高度一致，必要时随字体增长 |
| 表格行 | 约 26–30 个逻辑像素高 | 数值易读，容纳实际字体 |
| 工具栏图标 | 16–20 个逻辑像素 | 统一光学留白和线条重量 |
| 工具箱图标 | 24 个逻辑像素左右 | 图标与文字风格一致 |
| 普通圆角 | 2–4 个逻辑像素 | 不做大圆角卡片工作台 |
| 普通边界 | 约 1 个逻辑像素 | 选择和焦点再增强 |

实施要求：

- 以现有青色方向为品牌强调色基线；选择、当前页签和焦点共享明确语义。
- 分类颜色只在图标或小标记中使用，不让画布变成大面积彩色卡片。
- 业务 NG 和技术错误可以使用相近警示色，但必须通过文字/图标区分。
- QPalette、必要的局部样式、自绘控件和代理必须使用同一套令牌。
- 不把所有规则写成无边界的全局 QSS，不依靠字符串匹配业务类型选择样式。
- 字体用 Qt 逻辑尺寸体系；不要先手动乘显示缩放，再让 Qt 重复缩放。
- 可用现有 Fusion 风格，不为美化引入新的大体积 UI 依赖。
- 主题切换时图标、节点缓存、表格状态色和弹窗同步更新。

标准化组件至少覆盖：面板标题、局部工具条、图标按钮、页签、属性行、表格表头/行、状态标记、空状态和内联警告。

验收：同类控件在不同面板中对齐、尺寸和状态一致；浅色/深色下文字及焦点可辨；主题切换不需重开窗口。

### UI3.2 收敛主窗口与工具栏布局

主要位置：`editor_window.*`、`workspace_toolbox.*`、`workspace_icons.*`。

实施要求：

- 方案主工具栏按职责分组，减少每个动作都显示长文字；重要命令保留清楚标签。
- 文件、运行、视图三组有可辨边界，但避免过多粗分隔线。
- 主工具栏、流程工具栏、图像工具栏不能各有一套不同按钮高度。
- 方案名称、未保存状态和只读状态有稳定位置，不能长文本把核心操作挤出可视区。
- 多流程标签支持溢出与完整名称提示，不因名称过长撑破布局。
- 帮助和高级运行详情按需打开，不默认占据主要工作区域。
- 宽度不足时采用真实可用的溢出策略，不能仅设置固定最小宽度逃避小窗口适配。

工具抽屉需要支持：

1. 临时展开：尽量不让画布主体大幅跳动；覆盖层不能截获无关区域点击。
2. 固定展开：加入布局，宽度可调整并保存。
3. 清楚的固定/取消固定状态、Esc 关闭和键盘焦点返回。
4. 搜索、双击添加、拖放、无结果状态仍可用。
5. 拖放取消、窗口失焦和隐藏时清理临时状态，不能遗留错误光标。

如果临时覆盖实现会显著扩大风险，可先完成稳定的固定展开与不跳变布局，并把覆盖模式作为未完成项报告；不得宣称两种模式都已完成。

默认工具箱应区分生产工具与开发/模拟工具。开发工具可通过显式开关显示，但加载含开发工具的既有方案不能因此失败或隐藏已有节点。保留搜索可发现性，不将尚未实现的类别伪装成可用工具。

### UI3.3 改造节点视觉，不改变图语义

主要位置：`control_scene.*`、`control_graph_model.*`、工具图标和 UI 状态呈现层。

推荐普通节点结构：

```text
[工具图标]  显示序号 / 模块名称                [状态]
            可选的耗时或简短提示
```

实施要求：

- 名称左对齐，图标、标题、状态有稳定位置。
- 普通节点采用统一宽度区间；长名称省略并显示完整提示，不任意位置强行换行。
- 显示序号仅用于阅读，不作为持久化身份或绑定目标。
- 耗时可由全局显示选项、悬停或选中控制，避免所有节点持续扩张。
- 普通节点弱边界，选中和焦点明确，不新增重阴影。
- 执行状态与业务判定分开呈现；禁用、跳过、未运行有独立表示。
- 端口、分支标签、箭头和连线保持可读，普通续接的简化显示沿用合理现有行为。
- 绘制几何、端口位置、边界框、命中区域、连线端点必须一起更新，不能只改绘图。
- 节点尺寸不因运行耗时文字频繁变化而跳动；运行刷新不改变保存位置。
- 状态投影不修改方案草稿，不给撤销栈添加运行状态事件。
- Group、循环仍保持可辨识及进入/返回行为。

验收：选中、移动、拖线、框选、删除、撤销、双击配置、进入 Group 等操作与视觉位置一致；运行时节点不抖动、连线不断裂。

### UI3.4 增加显式自动整理，保留用户布局

优先复用已有整理能力；确无实现时，加入基于现有控制关系的最小可用整理，而不是扩展到复杂图优化研究。

实施要求：

- 普通流程优先采用稳定的纵向阅读方向，分支和合流保留明确空间。
- 已保存的节点位置始终优先，不在打开、切换页签或运行时自动覆盖。
- 自动整理由用户显式触发；明确作用于当前作用域或明确选择的节点集合。
- 整理作为一次可撤销编辑，保存/加载沿用现有布局字段。
- 大图处理要有可控耗时；当前作用域存在不支持的结构时解释限制，不破坏布局。
- 不因节点标题变化隐式改写所有节点坐标。

验收：整理后撤销能精确恢复原坐标；保存重开后布局不变；局部整理不移动其他流程或 Group 的节点。

### UI3.5 提升图像区有效面积

主要位置：`image_panel.*`、`image_view.*`、主窗口右侧分割器。

实施要求：

- 图像来源、轮次、跟随/锁定状态合并为紧凑头部，长来源默认省略并提供详情。
- 适应窗口、1:1、缩放等操作集中，不再散落多个不一致控件区。
- 图像尺寸、像素格式、缩放倍率和光标像素信息进入稳定高度的信息栏。
- 缩略图按需显示，无多个来源时避免持续占高。
- 图例在需要时显示，数量较多时可滚动或折叠，不无限压缩图像视口。
- 下方当前/历史结果允许折叠，并保留可恢复入口。
- 右侧默认比例可从图像约 70%–75% 开始验证，但不写死为不可调尺寸。
- 调整布局或打开日志不能悄悄清空图像缩放、平移、当前来源和历史锁定。
- 图像、叠加、取样坐标继续使用已有图像坐标变换，不能为适配 UI 修改算法结果。

验收：长文件名、长模块名和来源说明不导致视口反复跳动；缩放、取样和叠加仍一致；折叠/恢复结果区不会丢失浏览状态。

### UI3.6 布局记忆与恢复默认

将窗口几何、分割比例、工具箱固定状态、可见面板及合理的视图偏好保存到现有用户设置体系。不要将瞬时运行身份写成下次启动必需的持久化对象。

实施要求：

- QMainWindow 的状态保存与 QSplitter 状态分别处理，不能以为一个 `saveState()` 覆盖所有嵌套布局。
- 给设置增加布局版本，结构变更或损坏时安全回退。
- 更换分辨率、缩放或显示器后保证窗口和关键面板可见。
- 有明确的“恢复默认布局”入口，恢复布局不重置用户方案内容或设备参数。
- 模块配置窗口尺寸可记忆，但打开其他模块时不能继承不适用的内部编辑状态。
- 节点图位置仍按既有方案布局持久化，不挪到仅本机有效的用户设置中。

验收：重启恢复布局；损坏/旧版本设置能打开；恢复默认不会修改方案并触发无意义的未保存标记。

### UI3.7 文案、图标和可访问性整理

- 主界面统一使用中文用户术语：方案、流程、模块、工具组、运行、调试、执行状态、判定、历史等。
- 内部字段使用显示名，技术标识保留到详情；不要在翻译时修改持久化 ID。
- 使用一致线条重量和留白的图标，不混用风格差异显著的表情字符、系统位图和随机字母。
- 中文、数字、单位对齐清楚；耗时单位稳定，数值右对齐，缺值与零值不同。
- 图标按钮有工具提示和可访问名称；键盘焦点可见。
- 状态不只依赖颜色；菜单快捷键和常用键盘路径可用。
- 重点复查配置窗口、资源列表、历史表、图像信息栏、错误消息中的中英混杂。

## 10. UI4：端到端操作链与回归验收

### 阶段目标

证明工作台已经是一套连贯操作，而不是若干分别能打开的面板。该阶段必须执行真实验证，不能仅整理前面阶段的截图。

### UI4.1 复跑 UI0 的两组样例

用 UI0.5 的同版样例副本和相同输入复跑。五路检测核对两轮的 ROI、范围和 NG/OK；A→B 核对三组索引的交付值、分支和跳过原因，并从方案总览定位到报告中的子运行。验收报告并列记录 UI0 和 UI4 的结果。受环境限制的样例单列未验项。

### UI4.2 完成完整编辑与结果查看链

按以下步骤验证并记录结果：

1. 打开样例或新建方案，确认未保存/只读状态正确。
2. 从工具箱搜索并添加一个已有工具；验证双击与拖放入口。
3. 在配置窗口设置必要输入和参数；绑定与控制连接保持独立。
4. 执行当前流程，核对局部命令作用域。
5. 选择模块，查看对应图像、全部输出及当前结果。
6. 再执行一轮，选中历史并确认图像、输出、判定共同锁定。
7. 修改参数但不重跑，确认旧结果标记来源配置差异。
8. 重跑并切回跟随最新，确认联动更新。
9. 撤销/重做参数或布局操作，确认模型、选择、文案一致。
10. 保存、关闭、重新打开，确认方案数据和节点位置保持。
11. 使用原有 CLI 或无界面入口加载同一方案，验证 UI 未引入不兼容磁盘数据。

### UI4.3 完成连续运行、停止和切换链

仅使用真实支持的运行模式；不支持的项目明确标注不适用或后续范围。

验证步骤：

1. 启动受支持的连续/触发运行。
2. 锁定一条旧历史，确认新结果不会覆盖锁定内容。
3. 选中另一个模块，确认仍在锁定轮次。
4. 停止触发使用流程工具条。另从独立单次流程与整方案各运行一次，分别点击流程局部取消和顶栏取消，核对实际目标及历史锁定。
5. 用 UI1.5 的延迟退出用例复核取消已受理、方案报告已返回、最后一个子流程已退出三个时刻的状态。
6. 恢复跟随最新，确认结果一致。
7. 运行中关闭窗口或替换方案，验证既有确认、取消/排空及资源退出契约。
8. 模拟迟到通知，确认不能污染新文档。

真设备验证不是本阶段自动运行的前提。优先用现有模拟设备或可控测试夹具；实际相机/PLC 操作必须是明确纳入测试范围的操作，不因打开验收样例自动执行。

### UI4.4 覆盖异常和边界

至少检查：

| 情况 | 预期 |
|---|---|
| 空方案、无流程、无选中模块 | 清楚空状态，不崩溃，不显示不相关旧结果 |
| 必需输入缺失 | 提交前诊断或真实运行诊断可定位，不虚构默认输入 |
| 输出无效或未产出 | 字段仍可检查，显示原因 |
| 执行成功但业务 NG | 与执行失败区分 |
| 用户取消、执行超时、路径跳过 | 状态及原因可辨 |
| 历史容量淘汰 | 锁定行为符合策略，无悬空图像或无提示串轮 |
| 同一模块多次调用、锁定迭代后切换模块 | 复用 T08：选定迭代 0 的 A 后切到 B，核对 B 在该次的调用或缺失原因 |
| 资源失联 | 不阻塞主窗口，错误进入正确面板 |
| 长模块名、长路径、多流程 | 不撑破工具栏、表格和画布节点 |
| 只读方案 | 运行/编辑是否允许按现有规则，禁用原因明确 |
| 非视觉模块 | 输出/结果视图正常，图像区显示不适用 |
| 开发工具隐藏 | 已有包含开发工具的方案仍能显示和打开 |
| 恢复默认布局 | 不修改方案内容、不清理设备配置 |

### UI4.5 视觉测试矩阵

建议最低覆盖如下，实际能执行的组合记录在报告中：

| 维度 | 组合 |
|---|---|
| 主窗口尺寸 | 1280×720、1440×800、1920×1080 逻辑像素 |
| 显示缩放 | 100%、125%、150%。分别记录 Windows 原生显示倍率和 `QT_SCALE_FACTOR` 模拟倍率 |
| 主题 | 浅色、深色、跟随系统切换 |
| 内容 | 空白、短名称、长名称、多流程、多个图像来源 |
| 工作状态 | 编辑、运行、历史锁定、停止中、错误 |
| 面板状态 | 抽屉收起/固定、结果折叠、诊断展开 |

通过标准：无文字裁切、关键按钮遮挡、图标模糊异常、面板不可恢复、焦点不可见或图像轮次串用。颜色、阴影“看起来不错”不能替代这些断言。

### UI4.6 性能与资源检查

在与 UI0.6 相同的机器、Release 配置和离屏负载条件下重跑同一夹具，输出到 `ui4-desktop-load.json`。将两份 JSON 的六项 p95、Private Bytes 增量及图像释放数据并列，对照既有门限解释超限或明显退化。有影响的环境差异写在结果旁，缺少 UI0 实测时只报告本次测量。

实施要求：

- 连续通知到来时使用已有有界观察/合并刷新机制，不能每条通知全量重建所有表格和画布。
- 不在 GUI 线程执行设备 I/O、方案运行等待、整份大结果深遍历或无界图像转换。
- 选择变化可取消或忽略不再相关的异步展示任务。
- 历史、图像、缩略图缓存都有边界与释放点。
- 多次打开关闭配置窗口/资源窗口不累积信号连接和保留对象。
- 不用频繁 `processEvents()` 掩盖阻塞，也不为每个结果新建长期线程。
- 确认界面在连续运行期间仍可切换页签、关闭抽屉和发出停止命令。

报告实际测试条件、数据量、观察到的响应和内存变化。没有测量工具时，区分人工观察与量化结果。

## 11. UI5：后续扩展，按子项单独排期

UI5 不属于本轮必须完成范围。只有 UI4 达到对应基础门槛、且用户明确指定某个子项时再执行。

### UI5.A 完整方案图编辑

前置：真实方案模型、控制连接、公开映射、格式与保存契约已可用；先核实既有 F 阶段进展。

范围：方案入口编辑、流程间控制关系编辑、公开端口映射编辑、定位与诊断、撤销/重做、复制/导入影响处理。

验收：在桌面创建 A→B、配置映射、撤销恢复、保存重开，并由 CLI 加载同一文件得到一致关系；非法环、逆向依赖和多次供值等交由现有校验层诊断。

禁止：仅在 UI 图上画线而没有写入实际模型；为编辑方便绕过原有校验；把界面连接状态当成调度真相。

### UI5.B 专用模块配置编辑器

前置：UI2.5 的通用窗口、提交规则与结果浏览接口稳定。

范围：按节点逐个补齐 ROI、模板、标定、相机参数等专用内容，并复用通用输入绑定、运行状态和结果视图。

验收：每个节点独立给出配置往返、参数校验、撤销/重做、真实执行和结果显示用例；新增节点不要求重写主窗口。

禁止：一次替换全部 Inspector；节点专用窗口各自建立不同保存/运行规则；将展示元数据硬塞进算法业务逻辑。

### UI5.C 固定布局的运行视图

前置：明确方案运行生命周期及展示源配置。

范围：先做固定的操作员运行页，显示配置好的图像、关键结果、计数、设备状态和方案运行/停止；隐藏不必要的结构编辑入口。

验收：编辑视图与运行视图使用同一个活动方案和真实运行数据；切换视图不重复启动、不丢结果；控制作用域一致。

禁止：将隐藏编辑按钮当成完整权限系统；默认开启未授权的相机/PLC 副作用；复用历史浏览选择作为运行控制目标。

### UI5.D 运行界面设计器与高级布局

前置：固定运行视图和展示数据绑定契约已稳定，且有明确实际需求。

范围：多画面布局、结果控件、可配置绑定、布局保存和预览；完整编辑器能力另立详细计划。

验收：展示绑定有稳定身份、缺值行为、版本策略与安全运行边界；设计预览不触发真实设备动作。

本项不得以“UI 优化顺便实现”为由提前混入 UI1–UI4。

### 14.2 交付检查

提交阶段报告前：

- 检查实际 diff，确保没有无关格式化、缓存、二进制和临时文件混入。
- 执行 `git diff --check`，记录相关构建及测试结果。
- 检查所有新增可见按钮都有真实行为或明确禁用原因。
- 检查没有“TODO 返回成功”“假运行状态”或固定样例值进入正式功能。
- 不自动提交或推送代码，除非用户已明确要求；如需提交，按仓库约定拆分可审查改动。
- 未通过的验收项保持未勾选；不得用“代码已写完”替代验证结论。

## 16. 最终验收原则

本轮是否成功，不以“看起来更像海康”作为唯一标准，而以以下问题能否明确回答为准：

> 用户正在编辑哪个对象？正在查看哪一轮、哪份配置的结果？下一次运行或停止将作用于谁？界面是否始终给出一致答案？

在这个基础上，再评价视觉一致性、信息密度、图像有效面积、节点阅读性和操作效率。

**先收敛职责与交互，再统一视觉；先用已有节点跑通完整链路，再扩展节点细节和高级编辑器。**
