# 需求与阶段验收

## 1. 定位与设计标准

VisionPro 面向可配置的视觉应用开发，目标包含图像采集、视觉处理、结果判断和设备交互。
采用 C++20、Qt、OpenCV、CMake，当前仍处于基础设计阶段，尚无已验证的执行器或应用。

参考资料：[VisionMaster 用户手册 V3.0.2](Manual/VisionMaster算法平台用户手册V3.0.2.pdf)
及 [VisionMaster SDK 开发指南 V4.3.1（C++）](<Manual/VisionMaster算法平台SDK开发指南V4.3.1（C++）.chm>)。
用户手册提供业务行为依据，SDK 指南补充公开调用接口的依据；不同版本不混作同一份实现规范。
手册中可观察的功能构成需求依据；不把截图推断成线程实现，
也不要求复制其数量限制、文件格式、插件或 SDK。
C01–C10 是结合该依据形成的 VisionPro 设计基线，不宣称是参考软件内部架构。

文档明确区分：

- 目标能力：模型需要表达的功能，不因首版适配范围而降低。
- 不变量：身份、类型、所有权、作用域与结果一致性等必须始终遵守的规则。
- 可配置策略：工具/流程声明的状态寿命、并发准入、错误恢复、ROI 边界及资源读取行为。
- 阶段实现：本阶段实际支持并验收的子集；不支持的目标能力须明确诊断并保留配置。

普通节点支持多个前驱和后继，分叉与汇合不能降为单链。
单线程调度是实现选择，不是图模型的能力限制。
首批算法可以较少，ROI、坐标、类型和资源模型仍须能够表达目标场景。

## 3. 第一阶段：基础模型与契约设计

目标：形成支撑目标能力的概念、结构与不变量，明确首批实现范围和后续细化边界。

交付包括 C01–C10、模块依赖、两份手册的依据、设计理由、验收场景与实现待办。
SDK 补充的一次性输入、公开子图边界、输出有效性、事件交付及会话管理也纳入契约审查。
核心对象须说明身份、职责、寿命、所有权和是否持久化；
控制/数据/包含关系、状态/结果/共享值/消费消息均可分别表达。

设计审查通过条件：

- 图 3-2 的五路测量、条件检测和单次汇合可表达，不要求通过虚拟业务节点规避边数限制。
- 非相邻来源及合法兄弟分路数据依赖可表达；显式逆序依赖报错，绑定不触发来源。
- 实例寿命与状态寿命分开，初始化、重置、配置变更和在途状态代次有规则。
- ROI 不限于整数矩形，继承/修正/排除、坐标转换和越界策略明确。
- 本轮结果、合法无值、来源失败、选择器错误、NG、取消可以区分。
- 同步/异步完成、迟到回调、物理清理及共享设备连接的责任明确。
- 资源保留引用或嵌入可选；可编辑、可执行与可无损保存分别判断。
- C01–C10 每项都有来源、理由、正常/边界验收场景及阶段归属。
- 实现选择与剩余细化事项有明确落点，不以“以后扩展”代替目标契约。

本阶段通过文档和场景审查验证，不要求 GUI、真实算法、设备或执行器。
本次形成设计基线不自动表示阶段验收完成，后续状态必须有对应证据。

## 4. 第二阶段：核心模型与绑定验证

目标：将基线转为可构建、可测试的核心模型。

范围包括 CMake 核心目标、强类型标识、ConfigValue/DataValue、
Schema、控制/包含图、绑定、资源和状态定义，以及 BindingValidator/Resolver。
使用人工构造的结果验证常量、同流程引用、字段、固定索引和必要资源引用；
支持目标模型不等于立即实现全部工具、动态索引或资源服务。

验收要求：

- 无 GUI 编译测试；重复身份、无效字段、悬空引用、类型/作用域错误可定位。
- 五路分叉和多前驱汇合模型合法；错误普通回边和控制/数据依赖环被拒绝。
- 改名不破坏引用；复制重映射；缺少本轮结果不读历史。
- 必填性与 Optional 值类型分开，无损转换受声明约束。
- 图像共享、视图持有和配置/运行数据边界得到验证。
- 状态域、ROI 形状/掩膜/坐标与资源类别可以建模并校验。
- Workflow/Group 的公开端口、层级映射和类型化运行输入可表达；单次输入与持久配置不混用。
- 尚不要求真实调度器；人工构造数据不能记录成已完成执行验收。

## 5. 第三阶段：无 GUI 执行与配置往返验证

目标：通过模拟工具证明模型、绑定、执行、结果与存储一致。

必需范围：

- 静态工具注册表、实例工厂及受控同步/模拟异步调用。
- 顺序、无条件分叉、多前驱 AllActivated 汇合、基本条件分支及关闭传播。
- 配置快照、作用域/调用结果隔离、取消、错误诊断与来源追溯。
- 节点状态的独立性、每轮/会话状态、首次初始化和显式重置的模拟验证。
- 目录加 JSON 清单、托管/外部资源引用、配置往返及无 GUI 加载执行。
- 带诊断的编辑加载、未知内容保留限制和保存故障保护。
- RunRequest/RunHandle、单节点隔离调用、逐输出有效性与本轮结果快照。
- 模拟会话切换/关闭、回调排队/注销及观察通知与必需完成的分离。

允许先用单工作线程的就绪队列执行多分路。
此阶段准入策略为每流程最多一个在途运行，重复启动返回 Busy；
运行槽在实际清理结束后释放，无自动重试/隐式排队。
FailFast 是本阶段默认错误策略，NG 不自动终止；不因此禁止模型声明后续恢复策略。
实例可以每轮创建，但会话状态不得随实例销毁而丢失。
这些选择不得变成全方案只能运行一个流程或节点最多一个前驱/后继的模型限制。

推进顺序：先验证内存配置和模拟调用，再接入持久化；两部分共同构成阶段验收。
必须通过 §9 矩阵中全部标记 S3 的范围，包括 A09 图像所有权和 A22 结果保留的模拟部分。
五路全部完成后逻辑与模拟发送各一次，部分未选和零选不永久等待，
选中路径失败可结束等待，重复通知不增加调用次数。
数据依赖可细化未规定的控制顺序；B → A 与 B 读取 A 仍在执行前报错。

保存加载须保持身份、配置和相同输入下行为一致；不比较新运行标识、时间戳与耗时。
未实现的合法结构应在执行能力校验时报不支持，不能删掉后另存为单链。
模拟发送只记录调用和副作用次数，不连接真实设备，也不证明真实协议幂等性。

## 6. 第四阶段：无 GUI 视觉闭环

以“本地图像 → 二值化 → Blob 分析 → 结果判断”为首个真实算法样例。
箭头表达控制关系，图像和结果由独立绑定取得。
用固定图像和明确数值容差验证实际结果、失败路径、保存加载和无 GUI 执行。

该单链是算法样例，不替代第三阶段分叉/汇合要求。
增加共享图像、多区域读取及旋转/继承/修正 ROI 的代表测试，
验证坐标、实际区域与所有权，并覆盖栅格掩膜的成员判定、尺寸/坐标不匹配和空区域；
完整形状适配及标定工具可在第六阶段扩充。
像素计数面积与轮廓几何面积需说明定义，不能混用后只看“返回成功”。

本阶段不要求所有视觉算法，也不要求真实相机、TCP 或 PLC。
特征匹配、颜色测量等工具逐步加入；手册五路场景先完成模拟验证，真实对应工具完成后再补算法证据。

## 7. 第五阶段：基础可视化界面

实现可表达多前驱/多后继的流程画布、输入/参数配置、图像与结果显示。
界面复用同一领域模型、存储和执行服务；编辑器选型不能倒逼模型退化。

验收要求：

- 界面方案可由无 GUI 入口加载执行，相同配置和输入产生一致结果。
- 控制线、绑定来源与区域包含分别编辑；支持查看必要的数据依赖。
- 分叉/汇合、基本分支、非相邻绑定与布局往返可操作。
- 运行期间保持响应；编辑只影响后续快照。
- 历史结果带来源，预览不消费队列或触发业务副作用。
- 慢速显示不阻塞业务完成；关闭/重绑界面后，已注销订阅不访问销毁对象，旧会话通知不显示为新结果。

## 8. 第六阶段及后续能力

在既定契约上增加完整循环/区域导出、复合 Group 与独立子图导入导出、多流程并行、连续/外部触发、
重入/排队、共享服务、动态索引与计算/格式化、错误恢复/安全重试、
