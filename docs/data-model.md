## 2. 核心对象

| 对象 | 主要内容 | 生命周期 |
|---|---|---|
| Solution | 标识、名称、方案版本、流程集合、资源目录、全局变量及队列定义 | 方案配置 |
| Workflow | 标识、名称、公开输入输出、启用配置、节点和控制图 | 方案配置 |
| CompositeRegion（Group） | 区域身份、内部子图、公开端口与导出映射；区别于纯显示分组 | 方案配置 |
| RunRequest / RunHandle | 本次目标、固定输入及受理状态 / 已受理运行的等待、取消与结果查询 | 请求及单次运行 |
| Node | 模块配置：标识、工具类型、工具配置版本、输入绑定和参数绑定 | 方案配置 |
| ToolDescriptor | 类型标识、名称、参数与端口定义、能力说明 | 工具注册 |
| ToolInstance | 模块运行实例：执行方法、运行资源和受控状态访问 | 按节点隔离的执行或受控会话 |
| Binding | 输入或参数目标、取值来源、选择器、转换及可用性策略 | 节点配置 |
| OutputReference | 来源节点、输出或系统字段、结构化选择步骤 | 节点配置 |
| WorkflowLayout | 节点位置及必要的编辑布局 | 编辑配置 |
| ConfigSnapshot | 配置身份、一致参数及固定资源版本 | 不可变运行配置 |
| ExecutionPlan | 快照来源、工具版本、控制图、作用域及派生绑定约束 | 不可变计划，受执行器能力约束 |
| RunContext | 流程运行标识、快照来源、执行作用域、取消与输出 | 单次流程运行 |
| NodeResult | 调用身份、执行状态、输出、判定与诊断 | 单次节点调用 |
| GlobalVariableDefinition | 标识、名称、类型与初值 | 方案配置 |
| GlobalVariableEntry | 当前值、版本与更新来源 | 方案会话 |
| DataQueueDefinition | 标识、消息类型、容量与策略 | 方案配置 |
| QueueMessage | 序号、关联标识、生产来源与完整记录 | 入队至消费或按策略移除 |
| NodeState | 节点、状态代次、作用域、初始化与内部状态；重置策略在状态定义中 | 调用、流程运行或方案会话 |
| ResourceRef | 资源标识、类别与定位方式 | 方案配置 |

工具类型标识与节点标识分别管理。
同一工具类型可以对应多个参数不同的节点。

方案从数据结构上允许多个流程。
这不表示当前执行器已经支持多流程并发。
同一绑定只在节点配置中保存一份，流程级数据依赖索引由其派生。
配置定义与运行条目分开，不将当前共享值或消息积压放进 Solution 配置对象。

### 2.1 模块配置与运行实例（C01）

本文的“模块”和“工具”指同一类可执行能力：
ToolDescriptor 表示类型定义，Node 表示配置，ToolInstance 表示运行实例。
最终 C++ 类名可以调整，不同时维护语义重复的模型。

| 对象 | 保存的内容 | 禁止混入的内容 |
|---|---|---|
| ToolDescriptor | 输入输出、参数、状态能力与约束及执行能力元数据 | 某个节点的当前参数或累积值 |
| Node | 稳定身份、类型版本、参数与绑定配置，包括工具允许的状态初值和重置选择 | 运行句柄、当前结果和累积状态 |
| ConfigSnapshot | 一致的只读节点配置、类型版本及固定资源版本 | 可变编辑模型的借用引用 |
| ToolInstance | 执行对象、缓存及受控资源/状态访问 | 方案序列化逻辑和其他节点的可变实例 |
| NodeResult | 调用身份、输出、状态及诊断 | 可编辑配置和下次调用的可变工作区 |
| NodeState | 声明作用域内的累积或初始化状态 | 从历史输出隐式恢复的当前值 |

实例由配置快照和工厂创建；调用使用已解析并固定的输入。
创建失败报告节点诊断，不删除配置；编辑不改变运行快照，释放实例不删除 Node。

实例寿命与状态寿命分别声明。实例可按调用、流程运行或方案会话创建/复用；
NodeState 支持 Invocation、WorkflowRun、SolutionSession 作用域，见 §13。
实现选择每轮新建实例时，仍须通过状态服务访问按契约保留的会话状态，
不能随实例销毁隐式重置累加器，也不能把脚本首次初始化退化为每轮初始化。
不同节点的配置和可变状态相互隔离；同类型不构成共享可变实例的理由。

ToolDescriptor 声明同步/异步、可重入性、副作用、允许的状态作用域与配置约束、资源需求及取消/重试安全性。
工具允许节点选择状态初值、每轮初始化或跨轮累计等行为时，选择属于节点配置，不能成为同类型节点共用的固定值。
优先复用已声明、已校验的类型化节点参数，在快照/计划准备时生成该节点的有效状态规格；
状态配置参数在该准备边界固定，不在一次状态域存活期间通过普通取值改变其寿命或初值。
有效规格须满足工具的能力与约束，不新增任意状态配置字典，也不另存一份可独立编辑的参数副本。
S3.1 从固定参数生成有效规格，S3.5 用该规格创建或复用状态。当前接口见 §13。
业务 Init 由状态域协调；实例资源准备可随实例重建，不能重新执行已完成的业务 Init。
节点状态不存在两份可独立修改的副本。
配置变更按工具声明判断状态兼容性：兼容时保留，不兼容时创建新状态代次；
在途快照继续使用原代次，改名与布局变化不触发状态重置。
显式重置需与活动调用协调，不能清空仍被使用的状态。

逻辑终态不等于实例可销毁，实际调用与后台访问结束后才能释放。
设备连接由资源服务持有，实例释放只归还访问权，不误关其他使用者的连接。

### 2.2 运行组件与配置模型

| 组件 | 职责 |
|---|---|
| ToolRegistry | 静态注册类型描述与实例工厂，不负责保存当前工程 |
| BindingValidator | 校验来源、目标能力、类型、字段与结构依赖 |
| BindingResolver | 在具体调用上下文中解析有效值，不隐式执行来源 |
| ExecutionPlan::create | 从配置快照、工具元数据和执行器能力生成只读计划，拒绝所选执行范围内不合法或不支持的流程 |
| WorkflowEngine | 按合法控制关系创建或获取实例、组织调用并处理失败与取消 |

这些是运行服务，不是方案文件中的对象。
Workflow 保存执行关系；WorkflowEngine 使用模型，但不把线程或调度状态塞回模型。
RunContext 限定一次流程运行的状态，通过受控入口访问会话共享服务，
不兼任编辑器、方案存储或整个进程的全局字典。

### 2.3 工具调用与异步生命周期（C07）

InvocationOperation 是一次执行尝试的受控操作，拥有配置快照、本次输入、
状态/资源访问权、取消入口、完成通知及物理退出状态。
它与可复用的 ToolInstance、一次逻辑调用的身份分别建模。

- 同步接口在返回时交付已完成结果，不遗留未被追踪的本次后台业务操作。
- 异步接口返回受控操作句柄；输入、图像、实例及租约保留至实际访问结束。
- 工具可以返回声明过的控制出口选择；引擎校验并调度后继，工具不能自行调用后继。
- 初始化只准备状态、缓存和资源；采集、消费、发送等业务行为由显式操作完成。
- 预期错误返回类型化诊断；未预期异常在工作线程和 UI 回调边界转为诊断，不越界传播。

完成通知与物理退出可以不同步。取消或超时先关闭结果提交资格，
仍不能提前释放后台操作使用的内存和独占资源。
独立资源服务的常驻线程不属于同步工具遗留的调用，须有自己的停止与退出协议。
第三阶段以同步工具和可控制完成时机的模拟异步工具验证这些规则，不要求真实设备。

### 2.4 应用会话与管理操作（C01、C07、C09）

应用服务区分配置文档、活动方案会话和加载/保存/关闭操作。
管理操作有自己的 OperationId、进行状态、进度、结果及诊断，不借用节点调用的执行状态；
收到“加载结束”通知仍须检查其结果，不能仅按通知名称认定成功。

加载在候选上下文中解析、校验与准备，成功后切换活动方案；失败保留当前有效配置。
会话 Closing 后停止接收新运行、触发和修改命令，按声明的排空/取消策略结束活动操作。
会话关闭须等待调用、回调及资源访问退出，再释放状态、结果和连接。
保存取一致的配置修订，不把运行对象或一次性输入混入文件。

声明非线程安全的加载、导入、导出及设备管理命令由所属后端串行化，
与运行的互斥范围由能力表明确，不把后端管理限制推广为所有流程执行的全局锁。
若某外部后端只有进程单例、无法同时保留旧/新会话，切换须先停稳并采用已验证的恢复协议；
不能提供失败保护时拒绝该热切换方式，不谎称无缝切换成功。

进程级初始化与最终清理由 app 显式协调。正常资源仍采用 RAII；
有特殊退出时序的厂商 DisposeResource 等调用在受控 shutdown 阶段完成，
不依赖窗口或静态对象的析构顺序，也不让 UI 控件决定核心会话是否存活。

### 2.5 S2.4 方案、关系与编辑模型

[model.hpp](../include/visionpro/workflow/model.hpp) 属于独立的 `visionpro_workflow` 库，依赖 core，无 GUI 依赖。
`Solution` 保存正的格式版本与配置修订、流程、资源/变量/队列定义、坐标目录和独立布局；
`Node` 只保存身份、显示名、启用/汇合策略、工具类型与配置版本（或 Group 定义）、绑定和资源槽引用。
节点没有当前值、执行实例或结果容器。同类型节点的配置可独立编辑，改名与布局变化不会改写结构化引用。

`Workflow` 明确入口，并分别持有节点、`ControlLink`、`Containment`、公开 Schema 和导出映射。
控制线的空出口表示成功后的无条件连接，命名出口表示显式选择；多前驱/多后继不限制为单链。
`Containment` 只表达 Group 父子关系，节点最多一个 Group 父，不能形成包含环。
`children` 枚举当前层，`descendants` 按节点编辑顺序作深度优先枚举；编辑顺序不是调度顺序。
纯显示位置属于 `WorkflowLayout`，不会成为控制、数据或包含关系。

Group 复用 `NodeId` 表示可调用的容器，区别于 ROI 的 `RegionId`。
父级在 Group 节点的 Binding 中配置公开输入，子节点用 `ScopedInputReference` 读取该 Group 输入；
不另存一份可独立修改的输入映射。数据导出使用 `OutputMapping`，控制导出使用独立的
`ControlOutputMapping`（内部节点及其可选命名出口 → 公开控制出口）。Workflow 也持有这两类导出。
两者的实际类型、来源边界与控制可达性由 §5.6 的 Validator 检查，不能靠枚举公开端口认定可执行。

`validate_model_shape` 检查本地定义、方案内身份唯一性、包含树、当前层入口、公开目标唯一性、
资源/变量/队列/坐标定义及布局。`validate_public_interface` 复用 core 的输入/输出描述校验。
草稿可没有入口、没有完整导出或缺少工具注册；此局部入口不检查控制/数据引用是否存在、端口兼容或联合依赖环，
这些由 S2.5 的 `validate_solution` 统一负责。局部通过不等于方案可执行。

### 2.6 S2.4 配置快照

[snapshot.hpp](../include/visionpro/workflow/snapshot.hpp) 的 `ConfigSnapshot::capture` 从 const 配置及工具描述目录
复制可变容器、名称、绑定、布局和声明，内部共享 const 所有权；即使传入右值，也不接管调用者可能仍持别名的容器。
已封装的不可变 ConfigValue/Schema 可以安全共享。快照只暴露只读引用，使用借用引用期间须持有快照。
`SnapshotIdentity` 包含会话和快照计数，配置修订、方案格式版本、工具配置版本与它分别保存。
工具目录不允许重复类型，且每个 ToolDescriptor 必须局部合法。

捕获不会加载资源文件或锁定实际内容，只固定资源身份、版本/摘要及读取策略等配置声明；
捕获要求方案级不变量成立，保留带局部问题的配置和缺工具草稿供编辑诊断。
执行范围与工具能力由 `ExecutionPlan` 校验，详见 §5.8。

### 2.7 S2.7 工具实例、固定调用与操作

[core/tool_execution.hpp](../include/visionpro/core/tool_execution.hpp) 不依赖 workflow。
`ToolExecutionConfiguration` 复制并只读持有 Session/Snapshot/Workflow/Node、ToolDescriptor、
已固定的 SnapshotBuild 参数及资源槽；它是工具所需的配置投影，不复制一套可编辑 Node。
`ToolExecutionPolicy` 以有限枚举声明同步/异步、实例寿命、可重入性、副作用、取消和重试能力。
默认值为同步、按调用创建、串行、无副作用、不支持取消和不重试；声明能力不表示相应运行服务已实现。
同一实例固定到创建时的配置投影，不能用另一个节点或另一个配置对象的调用上下文启动。

`ToolInstanceFactory` 经 `create_tool_instance` 返回独立的 shared owning 实例或定位到节点的诊断。
空实例、配置不匹配和重复发行同一实例被拒绝；未预期异常转为 ExecutionBoundaryFailure。
实例与配置互不回写。S3.1 的 `ToolRegistry` 按工具类型固定元数据、版本能力与实例工厂，见 §5.8。

`InvocationContext` 复制并只读持有一次调用的 Session/Snapshot/Invocation/Attempt 身份、完整输入/参数、
已冻结的 ROI 来源和具名资源租约。缺值不能到这里再使用默认值，SnapshotBuild 参数也不能被替换。
`ResolvedRegionInput` 保留目标、原继承引用、完整源 RegionDefinition、生产调用及 Attempt、source_index/path；
含可写容器的源区域会复制，DataValue 和图像可共享只读存储。本层不执行几何计算。
`ResourceLease` 由具体适配器拥有，接口只暴露结构化资源引用；没有裸设备指针、任意服务字典或资源 I/O。
租约必须与固定资源槽的身份、类别和版本完全相符。S3.5 在状态工具的上下文附加类型化状态访问权。
缺少该访问权的状态工具调用返回 MissingCapability。

`InvocationOperation::start` 是显式工具调用入口，先检查固定配置、状态能力及实例可重入约束。
同步工具返回 ToolCompletion，返回时本次调用已经实际退出。异步工具先登记非空 InvocationControl，
再开始后台访问，并独立保留 InvocationCompletion token；登记后启动失败仍交回可查询、可取消和可等待的操作。
`complete` 只接收匹配身份与输出 Schema 的一次终态。`mark_exited` 独立报告后台访问结束。
操作等启动入口及在途取消回调返回，再完成自身持有对象的清理并发布实际退出。
逻辑完成不释放输入、图像、实例或资源租约；完成载荷复制后保持独立，重复/迟到完成不覆盖已有结果。
条件变量等待区分 LogicalCompletion 与 PhysicalExit；wait_for 的 TimedOut 只指等待期限，不创建工具超时结果。
S3.1 新增 `InvocationOperation::notify_when`，按逻辑完成和实际退出各允许一次登记。
接收者以弱引用登记，已达到的目标在登记时唤醒，随后达到的目标由报告线程唤醒。
`InvocationWakeup::signal` 在锁外传入调用身份与目标，接收方可查询进度并将通知放入调度队列。
实际退出和逻辑完成由不同线程报告时，接收方按查询到的进度处理。S3.3 的执行器接收这两类通知，详见 §4.7。
取消只表达协作请求。工具完成并不意味着 workflow 已接受结果，S3 仍需仲裁取消、超时、Attempt 和控制推进资格。
完整服务不得只依赖本操作的互斥保护来保证全流程提交或关闭的正确性。

[workflow/tool_execution.hpp](../include/visionpro/workflow/tool_execution.hpp) 提供层间投影。
`PreparedTool::create` 持有完整 ConfigSnapshot 与经过静态校验的 BindingResolver，
固定常量/default 及声明转换、聚合得到的 SnapshotBuild 参数；需要运行来源才能固定的参数明确拒绝。
`prepare` 先校验完整 ResolutionContext（包括无输入/参数的工具），再逐输入和参数调用 Resolver，
保留每个目标的值、来源和诊断，以 Failure > Unavailable > Pending > Prepared 的优先级汇总。
只有全部值就绪且租约匹配，才产生持有快照与 core InvocationContext 的 PreparedInvocation；此步骤不创建实例或启动工具。
`checked_node_result` 将匹配的 ToolCompletion 映射为 NodeResult，并复用 ResultStore 检查快照中的完整输出契约；
它不会插入真实仓库，也不会把工具完成误作引擎提交。
通过 `ExecutionPlan` 取得的 PreparedTool 复用计划范围和固定请求。独立调用按 §5.5 准备输入，
工具完成及结果投影按 §8.1.1 保留各输出可用性。

## 3. 标识与引用（C02）

不同类别使用强类型包装，不能无约束地互换。

| 类别 | 规则 |
|---|---|
| SolutionId、WorkflowId、NodeId、ResourceId、VariableId、QueueId | 使用 UUIDv4；持久化为规范字符串，加载时检查重复与引用一致性 |
| ToolTypeId、InputId、OutputId、ParameterId、FieldId、控制出口标识 | 在注册类型/对应模式中稳定；独立于可编辑显示名称；数据输出与控制出口不混用 |
| 控制连接及区域标识 | 在所属方案中稳定，供校验、编辑与追溯使用 |
| SolutionSessionId | 每次打开运行会话生成独立身份 |
| ConfigSnapshotId、WorkflowRunId | 在会话内分别递增且不复用；计数耗尽应报错，不能回绕 |
| ExecutionScopeId | 在一次流程运行内唯一；根作用域为 0，子作用域记录父域 |
| InvocationId | 标识一次逻辑调用；循环新迭代产生新调用 |
| AttemptId | 同一逻辑调用的执行尝试；重试递增，不改变逻辑调用身份 |
| FrameId、CorrelationId | 分别标识图像帧与业务关联，来源及唯一范围显式声明 |

改名、移动布局及保存加载保留身份。复制节点/子图生成新身份并重映射内部引用，
外部引用保留或解除须明确展示；删除后报告悬空引用。
“另存为”保留方案身份，“复制为新方案”生成新身份并完成内部重映射。
文件路径不是方案身份；两个副本被同时编辑时仍需文件修订/保存冲突检测。
外部 SDK 的显示名、模块整数 ID、执行次数或裸指针只作适配层映射；
映射还需限定后端会话/句柄代次，重载后旧回调不能映射到新对象。
外部计数不直接替代 WorkflowRunId、InvocationId 或 CorrelationId。

普通 OutputReference 保存来源 WorkflowId、NodeId、OutputId 或系统字段，
以及结构化的 Field(FieldId)、Element(IndexSource) 选择步骤。
例如界面可显示 `C.circles[0].radius`，文件不依赖可编辑名称解析。
IndexSource 支持固定整数和显式整数绑定；动态索引参与类型、依赖及循环引用校验。
第二阶段先实现固定索引，第六阶段实现动态选择/计算能力，不削减目标模型。

普通结果引用限定同一流程的当前运行及合法作用域。
跨流程通过共享变量、消息或显式汇合服务交换，不读取另一流程的“最近结果”。
配置引用不保存运行标识；解析器结合运行上下文定位具体调用，见 §8.2。
引用存在不表示可读取，还须检查类型、作用域、控制激活与结果可用性。
系统状态和诊断与算法输出分开；失败来源可供显式错误处理查询状态，不伪造有效算法数据。

### 3.1 S2.1 已实现的身份接口

公共类型见 [id.hpp](../include/visionpro/core/id.hpp)，创建入口见
[id_factory.hpp](../include/visionpro/core/id_factory.hpp)。
`SolutionId`、`WorkflowId`、`NodeId` 是互不转换的值类型，支持同类比较、复制和移动；
不能默认构造，也不接受裸字符串或字节数组构造。缺少身份以 `std::optional<Id>` 表达。
`IdFactory::parse<Id>(text)` 和 `IdFactory::generate<Id>()` 返回 `Result<Id>`。

内部保存按文本顺序排列的 16 字节，不采用 Windows GUID 的本机内存布局。
解析严格接受 36 字符的 `8-4-4-4-12` 十六进制文本，可包含大小写字母，
只接受 version 4、variant `10`；拒绝空白、括号、URN 前缀、尾随内容、nil 和其他版本/variant。
检查顺序为文本格式、version、variant；`to_string()` 始终产生小写规范文本。
UUIDv4 位布局依据 [RFC 9562 §5.4](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.4)。
生成采用 Windows 系统随机源，失败返回诊断，不退化为时间戳、计数器或固定种子。
随机生成不替代方案级重复身份校验；S2.4 的局部模型检查已验证唯一性，S2.5 的组合校验继续复用。

S2.2 扩充的身份见下一节；S2.4 的改名保持引用与复制重映射见 §3.3，删除后的悬空引用由 S2.5 校验。

### 3.2 S2.2 身份类别与有效范围

`ResourceId`、`VariableId`、`QueueId`、`ControlLinkId`、`RegionId` 复用 UUIDv4 值类型和工厂。
`SolutionSessionId` 也是独立 UUIDv4 类型，但不属于 `PersistentId`；`UuidIdentity` 包含两类，
不能将会话身份保存为方案持久身份。会话创建和实际身份分配由后续运行服务装配。

[schema_id.hpp](../include/visionpro/core/schema_id.hpp) 提供 `SchemaId`、`ToolTypeId`、
`InputId`、`OutputId`、`ParameterId`、`FieldId`、`ControlOutputId`、`EnumMemberId`、
`CapabilityId`、`CorrelationDomainId`、`CoordinateSystemId`。
它们是互不转换、区分大小写的稳定 token，使用
`SchemaIdFactory::parse<Id>` 创建，接受 1–128 字节的 `[A-Za-z_][A-Za-z0-9_.-]*`。
这些 token 在所属注册表/Schema/来源域内解释，不代表全局 UUID；中文显示名称独立保存为 UTF-8。

[runtime_id.hpp](../include/visionpro/core/runtime_id.hpp) 定义五类互不转换的 `uint64_t` 计数身份：
`ConfigSnapshotId`、`WorkflowRunId`、`InvocationId` 从 1 开始；`ExecutionScopeId` 的 0 为根，
`AttemptId` 的 0 为首次尝试。`RuntimeIdFactory::from_value` 检查有效下界，`next` 检查溢出。
`IdSequence<Id>` 不可复制、移动或重置，最大值只发出一次，耗尽后持续报告 `IdentityExhausted`。
序列由所属会话/流程/调用持有，不是线程安全的全局分配器；所有者和并发分配在 S3 接入。
显式指定下一身份的构造入口用于已知域的恢复与边界夹具，调用方不得在同一域重建序列复用旧值。

`InvocationKey` 按 §8.2 组合运行、节点、作用域和逻辑调用，`SessionInvocationKey` 再加入会话。
`AttemptId` 独立于逻辑调用键，重试不会生成另一种含义重复的调用身份。
`FrameId` 必须显式给出 `ResourceId` 来源与序号（允许 0），只在来源声明的寿命内唯一；
跨会话或设备重连时，后续运行层须补充上下文或保持同一来源域内序号不复用，不能直接当全局帧身份。
`CorrelationId` 由 `RuntimeIdFactory::correlation` 创建，包含来源域和 1–256 字节的有效 UTF-8 业务键，
禁止空键和嵌入 NUL；唯一范围与有效期仍由业务关联策略声明。
这些接口只验证身份表达与边界，不表示已实现结果存储、跨轮隔离或跨流程业务配对。

### 3.3 S2.4 复制与身份重映射

[copy.hpp](../include/visionpro/workflow/copy.hpp) 提供纯内存 `clone_subgraph` 和 `clone_solution`，
返回副本、分类的旧新身份映射及处理报告，不修改输入，不执行节点或操作文件。
子图复制用于同一 Workflow 内插入，选中 Group 自动包含全部后代；内部节点、控制线和 ROI 分配新身份。
绑定、公开输入引用、数据/控制导出、包含关系以及 ConfigValue 的 Record/List/Optional 内资源和几何引用递归重映射。
Group 的公开输入默认值及允许值集合也按相同规则处理。

调用者必须显式选择 `ExternalReferencePolicy::Preserve` 或 `Reject`。
保留的外部来源有类型化报告；选区外的包含父仅在 Preserve 下保留。
跨选区控制线报告并略过，不因复制自动接入外部执行链；流程入口、公开导出及布局不会被子图复制隐式追加。
整方案复制为 Solution、Workflow、Node、ControlLink、Resource、Variable、Queue 和 ROI 生成新身份，
同时重映射布局、引用及资源定义。工具/端口/Schema/坐标 token 不随实例复制变化。
资源路径、摘要和文件内容不因配置复制而自动搬运；需要独立资源副本时由后续持久化流程完成。
复制所需结构或外部引用策略失败时只返回诊断，不向原方案写入部分副本。

## 4. 参数、端口与值（C03）

ToolDescriptor 的参数/端口元数据至少声明稳定标识、类型、方向、基数、
必需性、默认值、范围或枚举、单位/坐标要求、允许的绑定来源及取值时机。
影响端口/记录模式的结构参数在计划生成前固定。
显示名称、分组、可见性和叠加样式独立于身份和业务值；隐藏参数仍参与校验。
训练、设备连接和刷新是显式命令，不是赋值的隐含副作用。

| 值族 | 设计要求 |
|---|---|
| 标量 | Bool、Int64、Float64、String、带定义的 Enum；算法需其他位宽时显式声明转换 |
| 二进制与图像 | Binary、Image；格式和所有权明确，不用任意载荷替代语义 |
| 几何 | 点、线、圆、位姿、变换、区域等，保留坐标系和单位 |
| Record | 由可校验 Schema 定义字段、FieldId 及字段类型 |
| List<T> | 空集合也保留元素类型；不因为空就失去类型 |
| Optional<T> | None 只表示契约允许的无值，不表示来源失败或仍在等待 |

ConfigValue 仅包含可编辑、可持久化的配置和资源引用。
DataValue 表达运行数据及受控所有权，不把图像缓冲、设备句柄、线程或结果历史塞进配置。
0、false、空集合、Optional 无值、尚未产生输出、来源失败和选择器错误分别表达。

第二阶段使用有限、可检查的类型表示；C++20 的 variant/记录实现方式不成为领域类型上限。
内置或由静态工具配置确定的 Schema 必须在计划生成前校验完成，
不能在执行中随意增删输出字段，也不用 std::any 或任意 JSON 字典作为核心值系统。
后续类型扩展需要标识、校验、所有权和序列化契约，不必为此提前引入动态插件 ABI。
例如标签图使用受 Schema 约束的“标签栅格＋类别表”记录，类别值/名称保留业务语义，
显示调色板独立配置；不能把伪彩图当作原始类别数据。该扩展示例不要求首批实现分割算法。
厂商枚举接口遗漏某类输出不证明字段不存在；适配器结合受版本约束的静态 Schema 补全，
无法可靠确定时报告能力不完整，不静默删除字段或退化为任意对象。
字符串参数及二进制长度查询接口须按已声明类型/编码/容量转换；读取期间长度变化或容量不足应报错/有界重试，
不能截断后冒充完整结果。

单个集合输入与多个来源是两个概念。
目标模型允许由元数据声明单来源、多来源和集合来源；第一批普通 Binding 解析一个来源，
多个来源通过显式聚合/计算/格式化工具组合，每个来源独立参与校验和追溯。
类型转换和可用性策略见 §5，不因界面可连接就视为类型兼容。

### 4.1 公开端口与一次性运行输入（C03、C04、C07）

Workflow 和 CompositeRegion 具有稳定的公开输入/输出 Schema，
公开端口用稳定 ID 绑定内部来源/目标；名称仅供显示和外部适配。
Schema 在生成快照前固定，可枚举类型、基数、必需性及来源能力。

RunRequest 至少包含目标身份、配置修订/快照选择、类型化输入集合、触发来源和可选业务关联。
类型化输入按公开 InputId 提交，并在受理时与快照原子配对；
不得通过全局可变的“先 SetInput、稍后 Run”槽位让两个调用串入对方数据。
拒绝/Busy 的请求不改变当前运行或下一次运行的输入，返回值明确是否已受理；
已受理返回 RunHandle 和新 WorkflowRunId，等待方式不改变执行语义。

输入在该逻辑运行中只读，并持有到全部实际使用结束；同一运行的安全重试复用固定输入，适配器按后端的逐次执行要求重新注入，而不重新读取实时来源。
新一轮必须重新提供必需外部输入，不能自动沿用上轮图像、ROI 或指针；
连续运行须声明每轮取数的提供者/触发策略，重复固定输入必须是显式配置。
运行输入不回写 Node，不随普通方案保存；资源固定配置与运行注入数据分别追溯。

内部绑定可以读取当前调用的公开端口（ScopedInputReference）。
只有元数据明确允许时，调用才可覆盖某输入/ROI/可动态参数；覆盖目标、优先级与实际值均入追溯，
不允许临时改变工具类型、输出 Schema 或控制结构。默认使用原绑定，不能因同名输入自动覆盖。
第三阶段先验证单流程类型化请求和模拟数据；Group 调度及完整调试界面按后续阶段实现。

### 4.2 S2.2 值系统与工具元数据实现

[value.hpp](../include/visionpro/core/value.hpp) 提供不可变 `DataType`、互不转换的 `ConfigValue` 和
`DataValue`。S2.2 加入 Bool、Int64、有限 Float64、UTF-8 String、原始 Binary、Enum、
Record、List 和 Optional；S2.3 的领域载荷见 §4.3。
值拥有其 Schema 和载荷，复制共享只读内容；工厂独立复制调用者的可变容器，即使传入右值也不接管可能仍有可写别名的分配。
调用方修改原字符串、字段、顶点或元素容器不改变已创建值；已封装的不可变子值和图像缓冲可安全共享。
没有默认无类型值，也不能通过任意 JSON、指针或 `std::any` 注入载荷。

Enum/Record Schema 使用独立 `SchemaId` 和非零版本。Enum 必须声明非空且唯一的 `EnumMemberId`；
Record 可以为空，但字段身份不能重复。类型相等同时比较类别、Schema 身份、版本及完整嵌套结构，
字段/成员的传入顺序和 Enum 显示名不影响类型相等。记录按字段身份规范排序，显示顺序不属于业务类型。
Record 值必须准确提供全部声明字段，未知、重复、缺失或类型错误均返回诊断；
Optional 字段也不能省略，合法无值必须显式提供 `None`。List 的每个元素须符合声明类型，
空 List 仍保留元素类型。Schema 工厂只接受已构造的子类型，形成有限的无环结构。

`ConfigValue::none(T)` 是 `Optional<T>` 的有效值，`some(value)` 显式包装；
未配置以外层 `std::optional<ConfigValue>` 的空状态表达，失败以 `Result<ConfigValue>` 的诊断分支表达。
0、false、空 List、None、未配置和失败均不相互替代。S2.6 通过 §5.7 的解析结果区分 Pending、正常不可用和来源失败。
当前 Float64 工厂拒绝 NaN/Infinity；String 严格校验 UTF-8 Unicode 标量值，保留合法 U+0000，
Binary 按字节持有且不推断编码。需要非有限数值或其他编码时，须显式扩展类型/适配契约。

[tool_descriptor.hpp](../include/visionpro/core/tool_descriptor.hpp) 提供参数、输入、数据输出及控制出口的
独立定义。输入/参数声明类型、必填性、默认值、范围、允许值集合、容量、允许来源、基数及取值时机；
数据输出与控制出口使用不同标识类别。端口的单位与坐标系是显式元数据；S2.3 校验几何自身及显式变换，
绑定两端的坐标语义由 S2.5/S2.6 校验，资源在 S2.6 中仅作目录引用解析，不由类型相等隐含转换。
配置版本 `config_version` 与工具 Schema 的身份/版本分别保存；S2.7 的执行能力和运行工厂接口见 §2.7。

`validate_descriptor` 检查重复身份、无效声明、默认值和约束，也拒绝同一描述内相同 Schema 身份/版本的冲突定义。
必填目标不能声明回退默认值，非必填目标必须声明合法默认值；值类型为 Optional 不改变这个规则。
整数和浮点范围分别比较，浮点界限必须有限；长度约束对 String/Binary 计字节，对 List 计元素，不截断。
约束可作用于 Optional 的实际载荷，None 不参与数值/长度比较；允许值集合可以显式排除 None。

`resolve_parameter_value` / `resolve_input_value` 仅处理已提供的配置值和默认值，
其 `nullopt` **只表示未配置来源**，不能由 Pending、本轮缺结果或来源运行失败代替。
已有诊断原样返回，类型错误和约束错误也不使用默认值回退。
绑定声明区分单来源、多来源和集合来源；多来源校验每个来源对 List 元素类型的兼容性，集合来源校验整个 List。
非订阅参数只允许常量，结构参数还必须在快照构建时固定。
精确类型匹配、`T → Optional<T>` 包装和显式 `Int64 → Float64` 是不同转换策略；
数值转换必须被目标明确允许且由调用方显式选择，不注册为普遍无损转换。
这些 core 接口只校验转换及多来源声明；S2.6 的 Resolver 执行已声明的转换、集合聚合、取值和来源追溯。

`validate_schema_support` 校验 Schema 身份、支持版本区间、所需能力及完整性声明。
适配器已知枚举不完整时必须设置 `complete=false` 并返回错误；此检查不会猜测厂商未声明的字段，
也不会删除现有定义。外部枚举与静态 Schema 的核对、实际字符串/二进制转换仍须在适配阶段验证。

### 4.3 S2.3 领域值与能力声明

两个值域均可持有经过校验的 `Point2D`、`Line2D`、`Circle2D`、`Pose2D`、`Transform2D`、
`RegionDefinition`（类型名 `Region2D`）及 `ResourceReference`。几何、ROI 和资源工厂先返回局部校验结果，
再建立不可变载荷；修改调用者的多边形顶点或排除集合不改变已建立值。
`ImageFrame` 和运行期 `RasterMask` 只存在于 `DataValue` 的载荷分支，配置域没有对应工厂或取值接口，
也不能通过 Record/List/Optional 嵌入运行值。`None<Image>`、空 `List<Image>` 可作为无像素的类型化初值；
它们不会隐式加载图像，`ResourceReference` 也不自动转换为 Image。

`ToolDescriptor` 新增可选的 `NodeStateDefinition`、资源槽 `ResourceRequirement`、
`RegionCapabilities` 和明确的 `PixelFormat` 列表。`validate_descriptor` 检查这些声明及重复项，
状态 Schema 参与同一工具的嵌套 Schema 一致性检查；资源槽不携带具体节点的资源实例。
`validate_image_support` 按完整格式匹配，空格式列表表示未声明图像支持，RGB 不等于 BGR。
`validate_region(region, capabilities)` 检查形状、边界、继承、修正和掩膜组合能力；
这些声明不启动算法、不加载资源，继承来源解析后的实际形状仍需后续校验。

### 4.4 S2.4 类型化单次请求

[run.hpp](../include/visionpro/workflow/run.hpp) 的 `RunRequest::create` 固定一个 ConfigSnapshot、
Workflow 或独立 Node/Group 目标、按 InputId 提供的 DataValue、触发来源及可选 CorrelationId。
普通节点使用快照中配置版本精确匹配的工具输入 Schema，Group/Workflow 使用各自公开输入 Schema。
目标或其所属流程/Group 被禁用时拒绝；临时启用须显式生成另一份配置快照。
独立目标默认声明 Isolated 调试状态，也可显式声明 Active；这不等于已获得活动状态的访问权或互斥许可。

请求校验未知/重复/必需输入、精确类型、数值范围、允许值和长度。
必需 Optional 输入仍须显式提交；未提交的非必需输入只使用本快照声明的默认值。
默认值作纯 ConfigValue → DataValue 物化，保留复合类型和 None，不加载资源或自动转换像素。
`FixedRunInput` 记录 Provided/Default 来源，输入容器独立持有、图像只读共享；每个新请求重新检查输入，
失败请求不会改写已有请求或从上一轮补图像。参数动态覆盖不在此接口中隐式开放。

请求还可持有调用方提供的只读全局值快照，逐项保留变量 ID、值、版本和更新来源。
构造时校验变量唯一性、定义类型及来源会话。缺少条目时运行绑定报告 GlobalUnavailable。
请求构造只固定输入与配置。S3.2 的运行服务负责分配 WorkflowRunId 和准入，见 §4.6。

### 4.5 S2.7 已受理运行句柄

[run_handle.hpp](../include/visionpro/workflow/run_handle.hpp) 定义 `RunSubmission` 三个互斥分支：
`RunHandle` 表示受理成功，`RunBusy` 指明占用中的运行身份，`RunRejected` 保存拒绝诊断。
`RunSubmitter` 是准入服务的接口，S3.2 由 `WorkflowEngine` 实现。
服务必须原子配对已准备的快照与输入；Busy/拒绝不得更改当前输入，也不得把被拒请求留下作为下一轮输入。

`RunControl` 在构造时持有 const RunRequest 和由其快照、目标及新 WorkflowRunId 组成的 RunIdentity。
`RunHandle::from_accepted` 只包装非空后端，不执行受理；只供已保留身份和请求的后端调用。
句柄复制共享拥有后端，移动后原句柄仍有效，与其他不可变模型一致。
销毁客户端句柄不隐式取消、不阻塞等待；后端必须独立保留活动操作直至实际退出。

`inspect` 返回逻辑状态、独立的 `quiescent` 和诊断。Pending 表示已受理但尚未开始；
Succeeded、Failed、Cancelled、TimedOut 是逻辑终态，Skipped 不是整轮运行终态。
`wait(Completion/Quiescence, steady_clock deadline)` 返回 Satisfied 或 DeadlineExpired 及同次进度快照；
等待期限到达不制造 TimedOut 运行，更不表示已释放内存或资源。
`cancel` 返回 Requested、AlreadyRequested 或 AlreadyCompleted。后端使用条件/事件通知，
提供线程安全的查询、等待和取消。S3.2 同步调用的取消边界见 §4.6。

`lookup(InvocationKey)` 不查询最近结果：校验当前 Run、目标 Workflow/Node（Group 包含其子节点），
并核对返回记录的 Session/Snapshot/Run/Invocation；已有 NodeResult 仍经过 ResultStore 的输出契约检查。
未记录的精确调用返回空 optional；这不推断来源已关闭或永远不会产生结果。
返回的不可变记录可独立保活。边界保留后端预期诊断，将不预期异常转为 ExecutionBoundaryFailure；
非法状态、矛盾等待结果和空后端返回 InvalidRunHandle。
这不替代后端对单调状态迁移、重复/迟到完成与提交资格的同步保护。

### 4.6 S3.2 内存执行闭环

[workflow_engine.hpp](../include/visionpro/workflow/workflow_engine.hpp) 的 `WorkflowEngine::create(registry)`
分配新的方案会话身份并启动一个工作线程。调用方使用 `engine.session()` 捕获快照，再构造 RunRequest。
`submit` 校验会话和计划能力，原子分配 WorkflowRunId 并占用目标 WorkflowId 的槽位。
同一流程跨快照的重复提交返回 RunBusy 和当前 RunIdentity。其他流程独立受理，按受理顺序在同一线程执行。
Busy 与校验拒绝不改写在途请求。已受理且待执行的流程通过句柄报告 Pending。
S3.2 首先受理 WorkflowTarget。NodeTarget 的独立执行和状态隔离见 §4.9。

工作线程沿显式入口和无条件控制边准备调用，使用请求的固定公开输入和只读全局值快照。
本轮使用根作用域 0 和首次尝试 0，并分配各调用的 InvocationId。绑定只选择本轮已经接受的来源调用。
逐个创建工具实例，经 InvocationOperation 完成同步调用，再由 `checked_node_result` 和 ResultStore 校验终态。
成功调用提交合法的输出槽并推进后继，包含 Judgement::NG。技术失败触发 FailFast，后继标记 Skipped。
已启动但结果无效的调用提交 Failed 记录与诊断。准备或创建实例失败的节点标记 Failed，调用键为空。
禁用节点关闭当前链，节点和后继分别记录 Disabled 和 UpstreamClosed。

`RunProgress.nodes` 按控制顺序记录节点状态、已启动的 InvocationKey、跳过原因和逐绑定的来源追溯。
客户端用调用键查询不可变 NodeResult，可从 ResultIdentity 读取本轮快照、调用及尝试身份。
每轮结果由对应 RunHandle 的后端持有，其他运行各用独立的结果仓库。

同步取消在准备、启动和结果提交边界检查。取消先于提交时，已启动调用在返回后记录 Cancelled，
未开始的后继记录 RunCancelled，先前已提交的节点结果仍可查。Completion 等待逻辑终态。
Quiescence 等待调用清理、计划释放及准入槽位归还。引擎销毁时排空已受理工作并等待工作线程退出，
客户端句柄在引擎退出后仍可读取已持有的结果。

### 4.7 S3.3 异步执行、取消与实际退出

S3.3 接通了同步与异步工具组成的线性计划。调用启动后登记逻辑完成和实际退出通知，
通知只携带调用身份和目标。执行器核对会话、快照、运行、节点、作用域、调用及尝试身份，
将当前运行标记为就绪。每轮合并唤醒，操作对象保留完成数据和退出状态。
单工作线程按受理顺序处理就绪运行，异步操作等待期间可推进其他流程。

结果校验后在同一运行控制锁内决定取消、发布结果及授予后继控制许可。
取消先于提交时，已启动调用提交 Cancelled 记录，已声明 Cooperative 的工具收到一次协作请求。
工具后来报告的完成用于操作收尾。取消后于节点提交时，已发布结果保留，未启动后继记录 RunCancelled。
同一线性流程在前一操作实际退出并释放准备持有的对象后才启动后继，启动边界再次检查取消。
流程逻辑终态可先于实际退出。Completion 和 Quiescence 分别等待上述两类状态。

调用方可在创建引擎时注入 `InvocationResourceProvider`。提供方负责资源访问权，规划检查其声明的资源类别。
`PreparedTool` 在绑定就绪后按固定资源槽获取租约并核对身份、类别和版本。
启动后操作持有工具实例和调用上下文。输入、图像及租约保留到退出和清理，流程槽位随后归还。
等待期限到达与丢弃句柄均保留在途工作的所有权。状态访问的持有期见 §13.1。

### 4.8 S3.4 分叉、汇合与基本分支

`WorkflowEngine` 对选定流程根作用域的无环计划维护控制边状态及节点就绪队列。
`RunProgress.nodes` 按计划的控制拓扑顺序记录节点，`control_links` 按边 ID 暴露 Pending、Arrived 或 Closed 及关闭原因。
显式入口提供一次虚拟到达，实际入边仍按 AllActivated 等待。成功完成时，无条件边全部获得控制许可，
命名边按工具的出口选择分别获得许可或关闭为 NotSelected。许可在对应操作实际退出及清理后交付。
全部入边正常关闭且没有虚拟到达时，节点记录跳过，并沿未执行的子路径继续关闭。
分支选择和禁用传播保留各自的原因，未执行节点的调用键为空。

同一流程的多个就绪节点可各自持有在途异步操作。单工作线程按完整调用及尝试身份消费通知，每个活动尝试合并自己的唤醒。
已获控制许可的节点使用原有绑定解析器准备数据。Pending 节点等待相关来源提交或确定缺失后重新入队。
已接受的兄弟结果可直接满足数据绑定，控制后继仍等待控制前驱退出。
绑定明确允许缺失时产生类型化 None 或按配置顺序聚合剩余来源。必需值缺失与解析失败分别保留原诊断，节点在准备阶段终止。

FailFast 在运行控制锁内关闭尚未确定的边并停止后续调度。已确定的到达与正常关闭保留原状态，
尚未提交的在途兄弟转为 Cancelled，并按工具能力请求协作退出。引擎持有流程槽位直至全部在途操作清理。
嵌套分支在同一作用域逐边传播。Group 执行与循环按后续阶段接入。

### 4.9 S3.5 状态服务与单节点调用

`WorkflowEngine` 受理普通工具的 NodeTarget。独立计划沿用同一流程的准入槽和唯一运行标识，仅包含目标节点。
已启用 Group 内的普通工具也可作为目标。Group 子图执行仍由后续阶段实现。
一次性输入通过稳定 InputId 固定，结果追溯记录 Provided 或 Default。无法满足的上游参数订阅在调用前报告诊断。

状态规格来自本次快照。默认 Isolated 调试调用创建临时代次。显式 Active 调试调用按普通执行的规则取得活动状态。
同一流程的运行和独立调用在实际清理前占用槽位。引擎通过 `reset_node_state(NodeTarget)` 对闲置流程中已就绪的、
声明允许显式重置的会话状态恢复配置初值。重置保留代次和已完成的 Init。
状态访问、配置兼容及修改时机见 [§13.1](#131-s35-状态访问与代次)。

### 4.10 S3.6 结果交付与会话生命周期

`WorkflowEngine::lookup_result(run, invocation)` 按完整运行和调用身份查询在途运行及已保留历史。
找到运行且对应调用尚无记录时返回空值。仍在索引中的运行须匹配会话、快照和流程。
同一会话已受理但已从索引淘汰的运行返回 ResultRetired。
`WorkflowEngineOptions::completed_run_limit` 默认为 16，按清理顺序保留，设为 0 时仅索引在途运行。
已有 RunHandle 和读取出的 NodeResult 各自持有不可变数据，可在淘汰或关闭后继续使用。

`WorkflowEngine::observe(capacity)` 建立会话内的独立观察队列，容量须为正数，默认 32。事件含单调序号、完整运行身份、
事件类型和状态。ResultPublished 附具体结果身份，RunCompleted 和 RunQuiescent 分别表示逻辑终态与实际清理。
队列满时淘汰最旧事件，`RunObservation::wait(deadline)` 返回事件、累计淘汰数与关闭状态。等待到期时返回空事件及当前状态。
`unsubscribe()` 清空该订阅并唤醒等待读取者。执行器只投递元数据，消费者自行读取及处理。
结果提交、控制推进和必要完成唤醒继续使用运行内部状态。

无 GUI 的 [WorkflowSession](../include/visionpro/workflow/workflow_session.hpp) 从 Empty 开始。
`activate(Solution)` 校验完整候选及工具版本与能力。准备期间仍可使用已发布会话，失败时保留它。
成功候选进入 Switching，停止旧会话受理并关闭旧观察队列，等待在途操作实际清理后发布新会话身份和快照。
提交要求持有该次发布的 ConfigSnapshot，复制该快照的句柄可用于构造请求。
管理进度由 `inspect()` 返回，使用独立的操作身份。Closing 期间停止新请求，排空结束后进入 Closed 并释放活动会话。
`close()` 使用排空策略，返回时在途调用、上下文和租约已清理。已持有结果的所有权继续由调用方管理。

## 5. 数据绑定与控制关系（C04、C06）

Binding 统一表达输入和可订阅参数：

| 内容 | 含义 |
|---|---|
| target | 当前节点的 InputId 或 ParameterId |
| source | 常量、当前运行输出、当前作用域公开输入、资源引用、版本化全局读取等已声明来源 |
| selector | Field、固定/动态 Element 等结构化选择步骤 |
| conversion | 无转换、已注册无损转换或显式转换策略 |
| availabilityPolicy | 必需、Optional、按原因回退或显式合并规则 |

输入源和结果订阅共用解析机制。源种类、基数、是否允许订阅由元数据约束；
并非所有参数自动支持全部来源。普通 Binding 不直接消费队列、发送通信或写共享值。
资源引用解析成能力/租约，采集工具才产生图像数据；触发请求新运行，不因值变化自动执行。

普通绑定支持精确类型匹配和 T → Optional<T> 包装。
可证明对源类型取值域无损的转换必须注册且被目标允许；Int64 → Float64 不能当作普遍无损。
有损数值转换、单位换算及坐标变换通过显式策略/工具执行并追溯，不能静默截断或猜测坐标系。
默认值用于未配置且允许默认的目标；来源失败不能自动替换成默认值。
绑定是否必填与值类型是否 Optional 是两维：必填的 Optional 输入仍须有合法来源，
可不配置的普通 T 输入则需有声明的默认值或其他明确规则。

控制、数据与包含是不同关系。ControlLink 连接控制出口和目标节点，不承载业务数据；
数据依赖从 Binding 派生，不另存一份可编辑的数据图。
节点位置不决定关系，绑定本身不激活来源或补跑副作用工具。

```text
控制：采集 A → 定位 B → 测量 C → 判断 D
绑定：B.inputImage ← A.image
      C.inputImage ← A.image
      C.positionTransform ← B.transform
      D.measuredValue ← C.radius
```

调用前固定本次输入与参数。全局读取可通过显式工具，或元数据允许的版本化 GlobalReference；
后者的批量一致性必须声明，不能声称多值属于同一工件。参数预览不消费消息或修改状态。
表达式、格式化、多来源组合及动态索引属于目标能力，先由显式工具提供，
不要求每个参数内嵌通用表达式引擎。

S2.4 的 [binding.hpp](../include/visionpro/workflow/binding.hpp) 已实现上述配置表示：
`BindingTarget` 区分 InputId/ParameterId，来源区分常量、OutputReference、ScopedInputReference、ResourceReference 和 GlobalReference。
结果引用区分 OutputId 与 SystemField，选择器当前实现 FieldSelection 与固定 ElementSelection，运行身份不进入配置。
源列表保留顺序，基数与显式转换策略独立。`AvailabilityPolicy` 可声明接受 NotSelected、Disabled 及合法的工具不产出原因。
Pending 保持等待，来源错误进入失败路径。
`validate_binding_shape` 只检查源数量、已知枚举及引用本身的基本形式，不访问结果、加载资源或消费消息。
来源/目标能力、选择器类型、作用域与图依赖由 S2.5 校验，接口见 §5.6；S2.6 取值与可用性接口见 §5.7。

### 5.1 可用性、等待与错误（C04）

| 情况 | 解析与执行要求 |
|---|---|
| 已提交值为 0、false 或空集合 | 有效值；访问空集合 [0] 仍报错 |
| 显式 Optional None，或已确定 NotSelected 且目标声明接受 | 按声明得到 None/合并缺项，不自动取历史值 |
| 成功调用按输出元数据合法地 NotProduced | 保留源输出的缺失原因；目标仅在显式接受该原因时得到 None/合并缺项，否则 InputUnavailable |
| 必需值确定不可用 | 在准备阶段报告 InputUnavailable，按错误策略结束等待，节点无工具调用 |
| 来源仍 Pending/执行中 | 不提前转成 None；仅等待已激活或可在合法控制路径激活且无等待环的生产者 |
| 来源 Failed、Cancelled、TimedOut | 保留诊断，Optional 不能吞掉错误；走显式错误策略 |
| 输出槽为 Invalid | 保留输出诊断，即使目标为 Optional 也不能转成 None；默认整次调用提交失败，局部容错另行声明 |
| 悬空引用、类型/字段错误、普通索引越界 | 定位绑定/选择器错误，不能返回零、None 或历史值 |
| 格式化工具明确声明的索引/范围容错 | 可忽略指定越界项或截取有效范围，记录实际采用项；不扩大到来源失败、错误类型或断连 |

结构错误在规划时拒绝，实际集合长度和来源终态在解析时判断。
回退必须明确允许的缺失原因并记录来源；普通绑定不支持 LatestAvailable/SpecificRun。
历史读取若引入，另行声明保留、过期和身份，不放宽当前运行引用。

数据依赖可细化控制图尚未规定的执行顺序，例如已激活兄弟分路间的读取。
它不得反转显式控制 B → A 来满足 B 读取 A，也不得激活未选分路。
规划同时检查控制/数据依赖和已声明的资源等待约束；运行时仍需处理动态资源状态。
第三阶段单工作线程可按合法就绪顺序调度，不要求图上节点排成一条链。

### 5.2 分叉、分支与控制汇合（C06）

普通节点允许多个前驱和多个后继；边数没有“最多一个”的领域限制。
一次成功完成可激活所有无条件后继，分支工具则从已声明出口中选择零个、一个或多个。
图中的多分路表达编排能力，不声称同时运行在多个物理线程。
工作流显式指定入口；未连接的编辑草稿不会因为入度为零就自动成为运行入口。
触发在本次作用域入口注入一次启动许可，等效为一条虚拟 Arrived 入边，使无前驱入口也可执行。
若入口还存在真实入边，仍须等待这些入边确定，启动许可不能绕过其前驱。
规划确定入口可达范围；范围外前驱仍连入待执行节点时报告执行范围不完整，不能留下永久 Pending。

首个汇合策略为 AllActivated，按流程运行和执行作用域管理各入边：

| 入边状态 | 含义 |
|---|---|
| Pending | 尚未确定是否到达；分支选择尚未确定也在此列 |
| Arrived | 本作用域有效控制到达，重复通知不重复计数 |
| Closed(reason) | 已确定不再到达，保留 NotSelected、失败、取消等原因 |

只有所有入边已确定、全部实际参与路径已完成，且至少一条有效 Arrived 时，
节点才可调用一次。未选路径须传播 NotSelected 关闭，不能留成永久 Pending。
所有入边均因正常未参与原因（NotSelected 或显式 Disabled）关闭时，节点记录未执行并向后传播关闭，不伪造调用或输出。
失败、取消和超时不等同于正常未选中；不能仅看到其他分路到达就忽略错误，
必须按 C08 的错误策略处理或显式恢复，解除后续等待。

普通无环区域中，同一节点在一个作用域内最多激活一次，不能因五个入边到达执行五次。
汇合策略属于节点控制配置及计划，不强制用户插入无业务意义的虚拟节点。
控制汇合不合成业务数据；MergeValues/格式化的来源、缺失与顺序另行声明。
嵌套分支也逐边传播关闭，不能用一个未限定作用域的全局“选中集合”判定齐备。
AnySelected 等提前继续策略需明确剩余工作的处置后再开放，不是当前默认。

手册图 3-2 对应的必须可表达场景：
定位 → 五个测量 → 各自条件检测 → 逻辑汇合 → 发送。
五个测量都激活，逻辑节点和发送节点各执行一次；所有数据仍经独立 Binding 获取。
第三阶段使用模拟工具验收此场景及按位多选/零选分支，不能只做单链执行。

### 5.3 结构化循环与作用域（C06）

普通无环区域不允许任意回边；重复执行通过显式循环区域表达。
循环配置包含起始值、终止值、步长及终点是否包含，步长不得为零；
边界方向决定零次迭代，计数溢出报错，不允许靠整数回绕退出。
起始值与终止值可采用工具允许的类型化绑定；每次进入循环时解析一次并固定本次循环边界，
解析使用本轮合法作用域中的数据，Pending、缺失与失败遵守 §5.1，不补跑来源或读取历史值。
动态来源不默认表示逐迭代追读变化；以后如支持每次迭代重新求终止值，须另行声明求值时机与可见来源。
迭代间隔以非负毫秒配置，默认零；表示前次迭代结束后、下次迭代启动前的等待，不是循环计数步长。
该等待必须可取消，不阻塞调度器处理其他就绪工作；取消后不创建下一次迭代。
每次迭代建立子作用域及新的 Invocation，支持嵌套且禁止隐式跨迭代读最近值。
循环内部可读取当前迭代和明确可见的外层结果。

区域外仅访问显式导出 First、Last、Collect 或 Reduce：
零次迭代时 First/Last 为声明的 Optional 无值，否则必需导出报错；
Collect 返回有元素类型的空集合，Reduce 使用显式初值，否则报缺少归约初值。
异常中断默认不发布完整成功导出；若需要部分结果，须声明完成标记、有效性和消费者。
正常提前退出须有显式控制出口及导出策略，不能伪装成迭代失败。
以上为 S6 目标契约；当前 C++ 配置模型尚无专门的循环配置类型，循环边界绑定、间隔及调度均未实现。
不能把普通 Group 或任意控制回边当作已支持的循环结构。

### 5.4 多流程、触发与并发（C06）

多个流程具有独立运行身份和上下文，可独立启动、停止并在目标执行器中并行推进。
单次、连续、外部触发、同流程重入和触发队列分别声明准入、容量与取消范围。
同一资源或状态域可串行化访问，不能因此把整个方案锁成只能运行一个流程。

第三阶段的运行准入策略是每流程 maxInFlight=1、重复启动返回 Busy、无隐式排队或自动重试；
可使用一个工作线程调度多个就绪分路，流程槽位至实际调用/清理结束才释放。
这是阶段策略，不是 Solution/Workflow 模型的能力上限，也不是方案全局互斥规则。
后续并行或重入须按工具、状态及资源声明隔离；不能仅增加线程数即视为完成。

### 5.5 复合子图、独立调用与启用策略（C01、C04、C06）

CompositeRegion（Group）封装有执行语义的子图，纯显示分组只影响布局。
Group 的每次调用建立子作用域；外部通过公开端口与显式导出访问，
不能穿透边界读取内部节点的最近结果。父级绑定经边界映射传入，区域内仍可表达分叉、汇合和嵌套。
普通 Group 不自动循环，循环仍使用 §5.3 的专门语义。

枚举接口区分当前层子节点和递归全部后代，保留稳定身份、父区域与顺序信息；
不能扁平化后丢掉包含关系。独立导入/调用的 Group 有显式宿主上下文及资源/状态访问能力，
不默认属于当前方案，也不能访问未注入的方案全局服务。

独立运行单节点/Group 是显式调试或调用命令，只执行目标及其内部子图，
不自动补跑外部来源或传播到目标之外的后继。调用方提供完整合法输入；
显式复用调试样本时复制/持有该数据并记为新调用输入，不冒充本轮上游输出。
它使用独立运行身份和明确状态策略：默认隔离调试状态，使用活动状态须显式请求并满足互斥；
不能通过“调试”绕过有副作用工具的执行及资源约束。

S3.1 的 NodeTarget 计划按目标工具输入 Schema 校验并固定本次提供的输入，
不再为了取得这些输入去解析目标在原流程中的上游绑定，也不要求目标由原流程入口可达。
原快照和节点配置保持不变，注入值记录为本次独立调用来源，不伪造上游调用或结果。
SnapshotBuild 参数继续使用固定配置；其余参数仍按工具声明的合法来源解析，
独立调用无法提供的运行订阅必须明确诊断，不能回退到最近结果或隐式执行来源。
执行范围、类型、资源及状态能力仍需校验；绕过外部控制编排不意味着绕过调用契约。
计划中的 PreparedTool 从 RunRequest 取值，在 `IndependentInputTrace` 记录输入身份与 Provided/Default 来源。
S3.5 的引擎直接执行这个计划并提交目标结果。准入、结果身份和状态策略见 §4.9。

方案级运行从启用集合中固定本次参与流程；被禁用的流程不进入新一轮计划，
直接运行禁用目标须显式临时启用并生成对应快照，不能静默忽略禁用配置。
运行中修改启用配置仅影响后续快照，停止当前运行使用专门命令。
Group 被禁用不等于结果可复用，也不自动把输入旁路成输出；
本次未调用及 Disabled 关闭原因须保留，它属于正常未参与但不是成功。
可选/合并消费者是否接受 Disabled 缺失由元数据声明，必需消费者仍按可用性规则处理。

第二阶段表达边界/层级及校验；第三阶段验证单节点隔离调用与输入规则；
完整 Group、独立子图及方案级多流程协调在第六阶段实现，UI 操作复用同一应用服务。

### 5.6 S2.5 静态校验与派生依赖

[validation.hpp](../include/visionpro/workflow/validation.hpp) 提供
`validate_solution(solution, tools, support = {}) -> Result<ValidationIndex>`。
它先复用 `validate_model_shape`，随后检查完整方案中所有配置节点，包括禁用节点与未连接草稿。
调用方也可传入 `snapshot.solution()`、`snapshot.tools()`；校验不改变编辑配置或快照。
失败返回首个 `Diagnostic`，保留方案/流程/节点、绑定输入或参数、输出或控制线，以及字段/索引路径。
错误后重新调用可继续定位修复后的下一项问题，不以日志字符串作为错误接口。

静态范围包括：

- 工具类型存在、配置版本精确匹配、Schema 完整性和同身份同版本的类型一致性；公开接口、全局变量及队列消息类型纳入同一检查。同版本工具/公开端口 Schema 的输入、参数、输出类型及控制出口身份必须一致，显示名称不参与比较。
- 控制边端点与命名出口、普通控制环、直接/间接逆序，以及纯数据和控制/数据联合依赖环；不因校验而重排控制线。
- 每个 Workflow/Group 的显式入口可达集合；范围外前驱连入可达节点、可达消费者绑定范围外生产者均拒绝。未连接的零入度节点不会自动参与。
- 输入/参数目标、必填性、默认值、来源许可、基数与声明转换；常量及可确定的集合长度执行静态约束检查，运行值约束继续在解析时校验。
- Record 字段与 List 固定索引逐步推导类型；不隐式解包 Optional，不猜测运行时 List 长度。静态合法的索引仍可能在 S2.6 报越界。
- 输出引用只能访问同 Workflow、同直接作用域的节点公开输出；公开输入来自当前直接宿主。嵌套 Group 必须逐层映射，不穿透内部或读取兄弟 Group 的内部节点。
- Workflow/Group 的每个公开数据/控制输出都有完整映射，来源位于内部直接作用域且控制可达；数据导出精确匹配类型和明确声明的坐标/单位。

`AvailabilityPolicy` 只允许 Optional 或显式多来源集合接受声明的正常缺失；禁用生产者需要显式接受 Disabled。
必填 Optional 没有绑定仍报错，默认值只用于未配置目标；配置错误不会回退到默认值。
快照构建期目标只接受固定常量，不能通过嵌套 ROI 继承取得运行输出。

静态引用检查递归进入 Record/List/Optional 的配置值及采用的默认值。
ROI source/exclusions 中的 `InheritedRegion` 需要目标允许 `RunOutput`，检查来源 Region2D 类型、坐标/单位、
作用域与启用/缺失策略，并纳入同一依赖环检查；不能用常量包装绕过订阅权限。
几何坐标目录、ROI 能力、Mask 和 Transform 的资源引用、节点资源槽，以及全局/状态/设备配置中的资源引用也按静态定义校验。
文件内容、实际图像尺寸、继承后真实形状和运行结果有效性仍由后续解析/算法适配检查。
没有调用上下文的初值不能引用运行 ROI；校验不会读取资源文件或执行共享读写。

通过时 `ValidationIndex.scopes` 按 Workflow 和可选 GroupId 保存独立 `ScopeDependencies`：
`reachable` 是显式入口可达节点，`control_links` 是该直接作用域的控制线，`data` 是绑定派生依赖。
每个 `DataDependency` 保留生产者、消费者、绑定目标、来源索引及是否来自 ROI 继承。
索引只持有身份与值，不借用可变模型指针；它不是持久化配置、调度顺序或运行就绪证明。
编辑模型变更后须重新校验，动态分支选择、Pending、失败和实际资源等待仍归运行阶段处理。

`support` 为空表示仅验证工具元数据；非空时，对使用的工具校验声明的 Schema 版本范围和能力。
该结果不代表厂商运行库、设备或执行后端已经运行验证。
S2.5 没有新增任意外层结果读取或循环语义；后续能力须显式声明边界，不能通过普通引用绕过当前作用域规则。

`system_field_type` 发布固定的系统结果绑定投影，由 S2.6 Resolver 复用：

| SystemField | 静态类型 |
|---|---|
| ExecutionStatus | `visionpro.execution_status` v1 Enum：Pending、Running、Succeeded、Failed、Skipped、Cancelled、TimedOut |
| Judgement | `visionpro.judgement` v1 Enum：NotEvaluated、OK、NG |
| Elapsed | Int64，单位为纳秒。未测量返回 InputUnavailable |
| Diagnostics | List of `visionpro.diagnostic` v1 Record：code(Int64)、severity(`visionpro.severity` v1 Enum：Info/Warning/Error)、message(String) |

Diagnostics 是可绑定投影，完整位置和其他诊断信息仍保留在 NodeResult 的 `Diagnostic` 记录中。
系统字段只有类型映射，没有读取旧结果或运行中轮询的权限。

### 5.7 S2.6 当前调用绑定解析

[resolver.hpp](../include/visionpro/workflow/resolver.hpp) 提供
`BindingResolver::create(snapshot) -> Result<BindingResolver>` 与
`resolve(context, target, results) -> BindingResolution`。
工厂先完成 S2.5 静态校验并持有不可变快照；解析输入/参数目标时使用同一快照和派生依赖索引。
当前实现已通过 Debug/Release 验证，实际记录见 development §8.9，不代表已有调度器或真实工具调用。

`ResolutionContext` 显式携带 RunIdentity、消费者 InvocationKey、运行作用域表、外层可见性、
来源调用选择及只读全局值快照。每个 `SourceSelection` 指定一个来源 NodeId 和运行作用域，
状态为尚无调用身份的 `AwaitingSource`、精确 InvocationId，或 NotSelected/Disabled。
没有来源选择是上下文错误；明确等待或指定调用尚无终态记录才返回 Pending。
未调用来源不伪造 NodeResult；普通引用不查询历史，不按 NodeId 或时间戳选择最新结果。

四类结果保持不同类型：

| BindingResolution 分支 | 含义 |
|---|---|
| ResolvedBinding | 当前已确定的 DataValue、各来源追溯和冻结的 ROI 来源 |
| PendingBinding | 当前来源未完成；只返回等待事实，不阻塞或补跑来源 |
| UnavailableBinding | 来源已确定不可用，包含原因、InputUnavailable 诊断和追溯 |
| BindingFailure | 来源失败、身份/上下文、选择器、类型或约束错误；保留原因诊断和追溯 |

多来源全部检查后，结果优先级为 **Failure > Unavailable > Pending > Resolved**，
防止来源顺序将已知错误隐藏为等待。Failed、Cancelled、TimedOut 分别返回来源错误，
失败输出的 Invalid 诊断进入原因列表，Optional 和默认值均不吞掉这些错误。
系统字段可读取已存终态的状态、判定、耗时和诊断；来源仍等待时也不读取上一轮系统字段。

正常缺失要求 Binding 明确接受对应原因。NotSelected、Disabled 来自控制选择；ToolDidNotProduce、ConditionNotMet 来自成功调用的输出槽。
单来源 Optional 产生类型化 None，多来源集合省略对应来源并保持其余配置顺序，追溯记录接受的原因。
合法 Available(None)、空 List、0 和 false 保持原值；没有 Binding 才采用已声明默认值。
Record 字段和固定 List 索引逐步访问，不隐式解包 Optional；实际越界返回 IndexOutOfRange。
Exact、WrapOptional 和显式 Int64→Float64 按声明执行；结果继续检查类型、范围、允许值集合和长度，
并检查真实几何坐标/单位、嵌套资源、ROI/掩膜能力和工具图像格式。
有具体工具时，其空 image_formats 表示未声明图像支持；来源结果和消费者均检查。
公开作用域输入尚无具体工具，仅作值与领域检查，消费时再检查工具能力。

`ResolutionScope` 的根为 0，父链必须有效无环；静态宿主是 Workflow 或 Group，公开输入属于具体运行作用域。
每个作用域重新检查必需输入、重复/未知输入、类型和约束；默认值只来自该公开接口，不能复用其他作用域输入。
`visible_outer_scopes` 只允许当前作用域的同静态宿主祖先，来源仍须明确选择其中的精确调用。
兄弟域、非祖先的其他迭代、其他 Workflow 和 Group 内部结果不因声明可见而变得可读。
Group 输入从当前宿主公开接口取值，Group 输出继续通过公开输出；没有循环调度或隐式边界穿透。

`GlobalReference` 只读 `context.globals` 中调用方提供的快照，检查变量、类型、来源会话和请求版本，
记录实际 revision/update_origin；未提供当前值报 GlobalUnavailable，不从定义初值补齐。
该容器不证明调用方进行了多变量原子读取，也不证明值属于同一工件。
资源来源仅校验目录身份、类别和版本，返回 DataValue 中的类型化 ResourceReference，
可固定目录已声明的版本并追溯；不读取文件、建立租约、连接设备、推进图像序列或把资源隐式变成 Image。

配置值与所用默认值中的 Record/List/Optional、ROI source/exclusions 会递归解析继承来源。
`ResolvedBinding.value` 保留原符号表达式，`regions` 的每个 `ResolvedRegionReference` 保存
完整来源 RegionDefinition、精确 ResultIdentity、来源索引和嵌套路径，包含来源自身的 exclusions/transform。
这些数据独立持有，不把来源简化成一个几何 primitive，也不丢掉外层修正或排除关系。
解析器验证实际来源坐标、形状及几何/掩膜组合能力；变换求值、区域布尔运算、栅格化和像素计算仍归算法层。
来源运行值与调用方提供的公开作用域输入必须已经完整，不允许再携带未解析 InheritedRegion；
只有待解析的配置表达式可保留这种引用并附带冻结来源。

解析不修改配置、ResultStore、全局快照或队列，不负责状态 Init、共享写入、设备调度、取消与实际执行。
来源追溯分别记录常量/默认值、精确结果调用与 Attempt、作用域公开输入、全局版本和资源引用。

### 5.8 S3.1 执行范围与计划

`validate_global_invariants` 检查方案头、方案内稳定身份唯一性及共享定义目录。
`diagnose_solution` 在全局检查和元数据校验通过后返回各流程的首条局部诊断及布局问题。
`validate_solution` 继续严格校验全方案，供编辑审查和既有解析入口使用。

[execution_plan.hpp](../include/visionpro/workflow/execution_plan.hpp) 的 `ExecutionPlan::create` 从 RunRequest 的快照和静态工具目录生成计划。
WorkflowTarget 从显式入口计算控制闭包。它检查所选流程的包含关系、范围内节点与公开映射、
范围外连入前驱、来源跨界、控制环和控制/数据联合依赖。快照保留全部配置，未参与的流程或断开节点可继续诊断编辑。
NodeTarget 计划只含指定工具，保留其静态所属关系。

[tool_registry.hpp](../include/visionpro/core/tool_registry.hpp) 的 `ToolRegistry` 拥有静态注册项中的工具描述、SchemaSupport 与工厂引用。
计划检查所选工具的注册契约、版本和能力。默认配置支持同步、按调用创建实例的线性流程。
调用方可声明支持分叉/汇合及命名控制连线、异步调用、节点状态或特定类型的资源租约。
带节点状态服务的执行配置可声明支持独立调用访问活动状态。Group 执行、持续实例和连续/外部触发归后续服务。
计划和检查过程无工厂调用。计划的 `create_instance` 仅接受范围内已启用的节点。

计划保留 RunRequest、入口和同一只读 ValidationIndex；每个 PreparedTool 复用该索引。
准备计划调用时，ResolutionContext 使用一个空的根作用域，公开输入和独立节点输入从固定请求取得。
流程内仍需明确选择本轮上游调用，独立调用无需上游来源。计划索引提供依赖信息，实际就绪及结果提交由执行服务处理。

## 6. 图像（C05）

图像对象需要明确：

- 尺寸。
- 像素格式、深度和通道顺序。
- 行步长。
- 缓冲区所有权。
- 数据来源或帧标识。
- 所属坐标系。

cv::Mat 可以作为内部存储，但不是完整的图像语义。
尤其不能只凭通道数量判断 RGB 或 BGR。
工具声明支持的像素格式、深度与通道顺序；首批 Mono8/彩色适配不成为 Image 类型上限。

所有图像工具遵守：

- 工具输入只读。
- 输出发布后只读共享。
- 需要修改时创建独立输出，或通过经证明的独占所有权保证其他读取者不受影响。
- 外部缓冲区显式绑定拥有者或先复制。

只读约定必须由接口和所有权设计落实，
不能仅依赖 const cv::Mat 阻止所有底层别名写入。

ImageFrame 描述帧身份、采集时间、格式及坐标信息；ImageHandle 表达缓冲区的受控所有权。
SDK/DMA 缓冲在驱动复用前必须完成复制，或通过有效租约延迟归还。
ROI/裁剪视图若共享原图内存，必须持有父缓冲所有权，且明确视图坐标到原图的变换。
取消或超时后仍在访问像素的后台调用也属于有效持有者，不能提前归还缓冲。
首批优先只读共享和显式独立输出；Copy-on-Write 与零拷贝优化须单独验证，不能作为默认性能承诺。
外部适配须联合校验格式、尺寸、步长、缓冲长度及整数乘法溢出，不能由 Width × Height 猜测任意格式长度。
SDK 结构只有指针/长度而未约定所有权时，按借用处理；在已确认的有效期内复制到本项目所有权，
或使用文档与测试均验证的租约。结构浅拷贝不延长像素/数组寿命，也不能猜测 SDK 指针的释放函数。

### 6.1 S2.3 图像实现

[image.hpp](../include/visionpro/core/image.hpp) 提供 `ImageLayout`、`PixelFormat`、`ImageHandle` 和 `ImageFrame`。
当前存储为标准 C++ 只读共享字节缓冲，无 OpenCV 依赖；支持 UInt8/UInt16/Float32/Float64 深度，
Mono/RGB/BGR/RGBA/BGRA 通道顺序，行内交错、本机字节序。其他编码由适配器显式转换。
`copy` 在外部借用有效时复制，校验非零尺寸、行步长、最小缓冲长度及乘加溢出；
最小长度为 `(height - 1) * row_stride + width * bytes_per_pixel`，末行不要求额外填充。

`crop(PixelRect, coordinateFrame)` 使用半开整数窗口，保留父缓冲所有权及步长，
记录到根图的坐标身份与累计像素平移。平移后的视图不能复用原坐标身份；嵌套裁剪不会复制像素。
`row` 只返回有效像素的只读借用 span，使用期间必须持有图像句柄。
`copy_pixels` 返回独立紧排字节，`clone` 返回独立只读图像并保留坐标映射；
修改导出的字节不会影响其他输入。句柄相等比较存储与视图身份，不进行逐像素比较。
帧身份和采集时间由 `ImageFrame` 可选持有，不由内存地址或时间接近推断业务关联。
当前无零拷贝租约、写入接口、设备适配或取消中的后台操作；这些生命周期另在后续阶段验证。

## 7. 几何、ROI 与坐标（C05）

图像原点为左上角像素中心 (0, 0)，x 向右、y 向下。
几何坐标使用浮点数，角度内部统一弧度；
在当前坐标系中从 +x 朝 +y 为正，图像坐标中表现为顺时针。
物理坐标系显式记录原点、轴方向、单位及手性，不把图像规则套用到机械坐标。
工具或 SDK 的角度、矩阵和单位约定由适配层转换。

Region2D 表达以下内容：

| 内容 | 规则 |
|---|---|
| geometry | 全图、轴对齐/旋转矩形、圆、环/扇环、多边形及显式栅格掩膜等区域表示 |
| coordinateFrame、localDirection | 所属坐标系及 ROI 局部轴/查找方向 |
| source | 本地绘制配置或继承的上游区域 |
| transform | 明确方向的可选位置修正/标定变换 |
| exclusions | 排除区域集合及各自坐标关系 |
| boundaryPolicy | 工具支持的 Reject、Intersect 或显式填充 |

RectI(x, y, width, height) 是像素访问窗口，使用左闭右开索引区间，
不能代替包含浮点中心、旋转方向和继承关系的通用 ROI。
工具元数据声明接受的区域形状和边界策略；不支持形状须诊断，
不得悄悄取外接矩形，或把浮点几何截断为整数。

Transform2D 声明 from/to、单位及模型，至少能表达相似、仿射、投影和受控标定映射。
组合前校验坐标系连接和有效域；求逆须明确请求且校验可逆，投影点落在无效域须报错。
Pose2D 仅在工具声明转换语义时才能产生 Transform2D。
圆经一般仿射/投影不再必然是圆，保留原几何与变换，或执行显式近似/栅格化并记录误差。

包含与排除区域在可比较坐标系中求实际区域，位置修正同时作用于局部方向。
越界不得隐式裁剪：Reject 报错，Intersect 使用交集，填充声明填充值/模式。
完全无交集或排除后为空时返回 EmptyRegion，由工具声明报错或有效空输出；
不默认把空区域当作整图。实际采用区域和转换来源进入追溯记录。

第二阶段确定模型和校验；第四阶段先实现所选算法需要的格式与区域适配，
并验证旋转/继承/修正 ROI 的代表场景；第六阶段扩充全部形状与标定能力。
阶段内未实现的适配不改变模型，也不能以仅支持整数矩形作为 C05 的目标契约。

RasterMask 保留只读像素所有权、掩膜坐标系、目标图像映射及有效像素规则，
不把一个普通 Image 值自动解释成区域。配置保存资源引用，调用时保存图像句柄。
工具声明可接受的掩膜格式、尺寸/步长和非零或阈值语义；尺寸或坐标不匹配必须报错或执行显式转换，
重采样方式须声明，不能默认缩放掩膜或由图像帧号相近推断对齐。
几何区域与掩膜互斥、组合或先栅格化由工具能力明确；厂商某工具的互斥规则不成为全局区域模型限制。
第四阶段用固定图像验证掩膜及不匹配边界，后续再扩充复杂组合。

### 7.1 S2.3 几何与区域实现

[coordinate.hpp](../include/visionpro/core/coordinate.hpp) 与 [geometry.hpp](../include/visionpro/core/geometry.hpp)
定义空间单位、坐标帧、点/线/圆/位姿、变换和区域。当前空间单位为 Pixel、Millimetre、Dimensionless；
未知或非空间单位、非有限数、退化线/圆和非法坐标轴均诊断。
坐标轴分量以向右 +X、向上 +Y 的参考基表示，因此图像轴为 `(1,0)`、`(0,-1)`，手性为 LeftHanded。

矩阵使用行主序 3×3 系数并作用于齐次列向量。相似、仿射、投影矩阵检查有限性和可逆性，
`map_point` 校验源坐标、单位、有效域和投影分母；`validate_transform_chain` 检查连接身份与单位，
不替代逐点有效域检查。`inverse_transform` 支持无界矩阵变换；有界变换不猜测逆域。
标定映射只接受固定版本资源与源有效域，尚无标定后端，实际映射或求逆明确返回不支持。

`RegionDefinition` 表达全图、显式空域、轴对齐/旋转矩形、圆、环、扇环、多边形和配置掩膜，
区分本地 `RegionPrimitive` 与结构化 `InheritedRegion`，持有源与排除项各自的位置修正和局部方向，以及区域的边界/空域策略。
多边形检查有限坐标、非零面积、重复相邻顶点和自交；工具不支持形状时拒绝，不取外接矩形。
`MaskConfig` 保存资源引用与格式/映射声明，不持像素；`RasterMask` 持只读图像。
两者均显式声明目标尺寸/坐标、非零或阈值规则和重采样策略。
直接掩膜必须尺寸/坐标一致；变换掩膜必须声明连接正确的像素坐标变换及采样方式。
`validate_raster_mask(mask, image)` 可核对实际目标图像，`validate_region_frames` 可核对坐标目录。

本阶段只验证模型及上述矩阵数值行为，未计算区域交集、排除后成员、真实越界或掩膜像素成员，
也未执行几何栅格化、重采样、校正局部方向或算法适配。空域策略覆盖显式空域，
由实际裁剪/排除计算出的空域及浮点几何到像素的规则仍在 S4/S6 验证。

## 8. 运行与结果（C02、C08）

### 8.1 状态维度

| 维度 | 含义与边界 |
|---|---|
| 工具实例生命周期 | 创建、初始化、可调用及释放；不代替每次调用状态 |
| 流程运行/节点调用状态 | 是否等待、执行或终止；流程摘要与各节点状态分别保存 |
| 检测判定 | NotEvaluated、OK、NG；不与技术执行成功等同 |
| 资源连接状态 | 连接、断开、恢复等，由资源服务维护，不以 NodeResult 作为设备健康状态 |

执行状态分开记录等待、执行与终止：

- Pending。
- Running。
- Succeeded。
- Failed。
- Skipped。
- Cancelled。
- TimedOut（在引入超时能力时明确，不能与主动取消混淆）。

检测判定：

- NotEvaluated。
- OK。
- NG。

成功执行可以得到 NG。
没有检测判定的工具不应被强制标记为 OK。

节点结果至少包含：

- 流程运行、节点、执行作用域与调用标识。
- 执行状态。
- 各输出端口的有效值。
- 检测判定。
- 诊断信息。
- 耗时。

### 8.1.1 输出级有效性

NodeResult 对每个已声明输出记录 OutputId、类型、可用性与必要诊断；
可用性至少区分 Available、NotProduced(reason)、Invalid(diagnostic)。
Available 的值仍可能是 Optional None 或空 List，两者与未产生/失效输出不同。
必需输出在成功提交前必须 Available；缺失或失效使契约校验失败。
输出元数据须声明必需性，以及非必需输出允许不产生的原因；未作声明时按必需输出处理。
例如工具声明“条件不满足时不输出”时，可提交成功调用及对应 NotProduced 原因，
不把源输出记录改成 Optional None、空集合、技术失败或控制分支未选中。
允许不产生的输出须逐槽携带声明过的原因，消费者按 C04 的来源与缺失策略判定；
需要接受此类缺失的绑定也须显式声明，不能只看数量为零就当有效空集合。
任一已声明输出的 Invalid 默认使整次调用提交失败，不能因为该输出非必需就自动吞掉或降成 NotProduced；
非必需输出仅可按元数据声明的原因不产生。如工具支持局部容错，须显式声明输出有效性及允许的消费者，
不放宽默认失败无算法输出规则。

外部适配分别检查调用错误、单个输出状态、元素数量和缓冲一致性。
例如参考 SDK 的 ImageResultInfo.nValueStatus 以 1 表示成功，而 MVD_OK 为 0；
不同状态域不能统一按“非零就是错误”转换。输出级状态不等于业务 OK/NG。
Failed/Cancelled/TimedOut 默认不发布算法输出的规则仍然有效，
SDK 暴露局部结果并不自动授权本项目将失败输出用于普通绑定。

S3.1 的 `OutputDescriptor` 增加 `required` 和 `allowed_absence`，默认要求可用值。
非必需输出须声明 ToolDidNotProduce 或 ConditionNotMet 等允许原因。成功的 `ToolCompletion` 逐槽报告
DataValue 或允许的 NotProduced，缺少槽位或报告 Invalid 都会被拒绝。
`checked_node_result` 复用完成校验并物化 NodeResult。失败完成可保留 Invalid 槽的错误诊断，
其余声明输出按失败、取消或超时原因物化。ResultStore 复查输出契约，BindingResolver 按消费者的缺失策略取值。

### 8.2 运行、调用与尝试身份

结果身份表达为：

```text
InvocationKey = { workflowRunId, nodeId, executionScopeId, invocationId }
OutputAddress = { invocationKey, outputId }
```

ResultStore 以方案会话为边界；结果离开会话或写入追溯记录时补充 SolutionSessionId。
流程运行标识在方案会话内唯一，作用域标识区分循环、容器和嵌套调用。
InvocationId 标识一次逻辑调用，同一节点重复激活或进入新迭代时产生新调用。
后续重试沿用该 InvocationKey，以 AttemptId 区分各次尝试；不另设含义重叠的 ActivationId。
ResultStore 按调用保存有效输出，不能只用 NodeId 覆盖一个最新结果。
未激活或因依赖跳过的节点可有执行跟踪记录，不为此伪造工具调用；
流程摘要中的 Skipped 与实际调用的终态须能区分。

| 身份 | 用途 |
|---|---|
| ConfigSnapshotId | 识别本轮使用的不可变配置；不同于方案文件格式版本和工具配置版本 |
| ExecutionScopeId | 标识本次区域/迭代上下文；后续可附带父作用域和结构化迭代路径用于追溯 |
| AttemptId | 区分一次逻辑调用的尝试；首版不重试，不提前实现通用尝试调度框架 |
| FrameId | 标识来源图像；采集设备内计数需与来源身份组合，不能假定全局唯一 |
| CorrelationId | 关联同一工件或业务请求，可跨多个 WorkflowRunId；InspectionId 可作为其业务名称 |

CorrelationId 必须由业务触发源或已定义的关联策略产生，并明确唯一范围与有效期。
时间接近、帧序号相等或各队列的第 n 条消息都不能单独证明属于同一工件。

配置引用不保存运行标识；BindingResolver 结合当前执行上下文，
解析到本次允许读取的来源调用。存在多个候选时必须按作用域规则消歧，
不能按时间戳随意选最新结果。
循环内部默认读取当前迭代或明确可见的外层结果，不能隐式读取其他迭代最近值。
循环外通过 §5.3 的区域导出或聚合规则读取 Last/First/Collect/Reduce，
不能只凭内部 NodeId 取得最后一次输出。
界面可显示历史结果，但需标注来源，历史索引不能成为执行器的取值依据。

### 8.2.1 S2.4 结果身份与独立记录

`RunIdentity` 组合 SnapshotIdentity、WorkflowId、WorkflowRunId，`ResultIdentity` 再包含 InvocationKey 和 AttemptId；
`OutputAddress` 使用 SessionInvocationKey 和 OutputId，重试编号留在追溯身份中，不改写逻辑调用地址。
`NodeResult::create` 从独立的 `NodeResultData` 复制不可变记录，校验运行身份与调用键一致、非负耗时、
执行状态/判定、输出类型/可用性、控制选择唯一性及诊断。Succeeded+NG 是合法成功；
Failed 必须带错误诊断，失败/取消/超时不能携带 Available 算法输出或正常控制选择。
Available(None)、Available(空 List)、NotProduced(reason) 与 Invalid(diagnostic) 保持不同分支。
Pending/Running/Skipped 不创建终态调用结果，未调用节点需由后续执行跟踪记录表达。

该对象本身没有提交资格或已发布含义，不核对工具声明的全部输出，也不验证某调用是否真实存在。
S2.6 的 ResultStore 补充完整输出校验和精确结果访问；取消竞争、真实调用与一次提交服务继续归 S3。

### 8.2.2 S2.6 会话内结果访问

[result_store.hpp](../include/visionpro/workflow/result_store.hpp) 的 `ResultStore(session)` 是
**单线程、会话内的终态记录容器**。执行受理、重试仲裁及并发提交由运行服务负责。
`insert(snapshot, result)` 要求仓库会话、结果 RunIdentity、SnapshotIdentity 和 InvocationKey 一致；
同一 WorkflowRunId 首次固定其 Workflow/快照，不能改用于其他流程或配置。
仓库按完整 InvocationKey 存储，重复逻辑调用返回 DuplicateResult，即使 AttemptId 不同也不覆盖旧记录。

插入检查节点和工具版本、声明输出身份/精确类型、控制出口，以及运行值中的资源、坐标和能力。
Succeeded 必须对每个声明输出提供 Available 或元数据许可的 NotProduced。Optional None 与空 List 都是 Available 值。
失败/取消/超时保留其终态与诊断，不能带 Available 算法输出。运行输出中的 ROI 必须完整，
不得包含未解析 InheritedRegion，以免结果读取引入第二层隐式运行依赖。

`lookup(run, invocation)` 只按精确身份返回持有所有权的 NodeResult 或明确的“当前无记录”，
身份冲突与已退役运行分别报错，不提供 latest 查询，也不从旧作用域补值。
`release_run(run)` 移除该运行索引并记住其退役身份，迟到记录不能重新占用这个 RunId；
即使从未插入结果，也可显式退役。已返回的记录、值和图像仍保持自身只读所有权，释放索引不会使其悬空。
S2.6 验证人工记录的重复拒绝、隔离与保活。S3.2 的同步运行服务按 §4.6 将校验后的实际调用结果提交到每轮仓库。

### 8.3 结果提交、取消与副作用

工具先构造私有暂存结果，引擎校验输出类型、调用身份及提交资格后，
原子发布最终输出和终态。每个逻辑调用只允许一次最终提交。
允许重试时，可重试的中间失败尝试仅留追溯记录，不结束逻辑调用；
最终技术失败在无重试或重试耗尽时须提交一次 Failed 终态和诊断，不能永久保持等待，也不提交有效算法输出。
最终取消或超时分别保持 Cancelled、TimedOut，不因没有重试而改写成 Failed。
成功执行且检测 NG 可以发布有效输出；Failed、Skipped、Cancelled、TimedOut
默认只提供系统状态和诊断，不发布可供普通绑定消费的算法输出。
部分成功输出若成为需求，须单独声明字段有效性及允许的消费者。

取消/超时与结果提交的竞争由同一受控终态转换裁决：
若提交已被接受，随后取消不改写既有结果，但可阻止后续调度；
若取消、超时或尝试替换先被接受，旧结果不可再提交。
未获接受的、重复的及过期的回调不能覆盖终态、发布结果或推进控制出口。
检查资格、提交以及生成控制完成事件须保证一致，不能检查后再无条件发送完成通知。
后继即使已进入就绪队列，真正启动前也须重新检查取消，防止提交后取消仍启动发送。

取消请求与节点终态分开：
提出取消请求，不意味着正在运行的工具已经停止，也不保证已发送的外部指令被撤销。
结果仓库可先关闭提交入口，但工作线程、缓冲区和资源租约须在实际操作退出后释放。
清理未完成时不能重入同一实例或重新占用尚未释放的独占资源。

第三阶段默认 FailFast：未处理的技术失败终止本轮后续调度，NG 本身不终止。
目标支持继续独立路径、显式错误处理及受控重试，由节点/流程策略和工具能力共同约束。
错误被处理不改写原节点 Failed；流程摘要区分已处理与未处理错误，并按声明策略决定结束状态。
最终失败关闭正常控制出口，只允许声明的错误出口进入处理路径；无处理策略时传播失败/中止原因。
恢复后能否回到正常路径须显式连接并提供所需数据，不能凭错误已处理就制造缺失的算法输出。
重试中间失败不能提前传播最终错误出口；只有逻辑调用的最终接受状态推动控制。
第三阶段不自动重试。以后引入重试须分别声明计算、工具状态、队列消费及外部操作的重试安全性。
响应丢失可能意味着外部操作已完成，不能以本地超时推断操作未发生。
幂等协议采用对同一逻辑操作稳定的键；它不随 AttemptId 改变，也不能仅用工件标识区分全部操作。
一次调用有多次写入时还需区分操作序号或操作身份。
结果提交的原子性不涵盖外部写入、队列出队或工具状态修改；拒绝结果不表示这些副作用已回滚。

### 8.4 保留与释放

本轮结果保留至所需消费者完成；跨出 ResultStore 的视图必须明确持有所有权或受限借用期。
ResultStore 释放本轮索引不应使仍被有效持有的图像悬空。
显示历史、队列、共享值和工具缓存分别设置保留策略，并纳入内存预算。
历史缓存淘汰只释放自己的引用，不得强制回收活动消费者正在使用的内存。
内存压力下优先按策略淘汰仅供显示的历史；业务消息和运行必需输入只能按声明的容量策略处理。
具体预算数值留待实现测量，不以引用计数或 TTL 本身保证内存有界。

### 8.5 结果获取与事件订阅（C02、C07、C08）

按 RunHandle/InvocationKey 获取不可变结果快照或受控 ResultLease，
不暴露需要反复 GetResult 刷新、可能随下一轮覆盖的外部对象作为运行数据。
适配层在对应完成边界一次物化所需字段并关联本次身份，字段读取不触发再次执行。
S3.6 的会话历史按完成清理的运行数量保留，淘汰后按原身份查询返回 ResultRetired。
活动绑定和已持有结果的所有权遵循 §8.4。具体查询与观察接口见 [§4.10](#410-s36-结果交付与会话生命周期)。

区分内部完成事件、业务结果交付及 UI/日志观察通知：
关闭可选显示订阅不影响 ResultStore 提交、控制推进或必需消费者。
必需通道不能按显示节流策略丢弃；显示通道可合并过时刷新，但须保留来源身份和可观测丢帧/合并计数。
各通道有容量/超限策略，不能通过无界积压绕过缓冲预算。
必需完成通道须按在途上限预留交付容量或使用可验证的独立完成状态；
不能在外部回调中无限阻塞，也不能队满后丢失唯一终态通知，超载应在准入处拒绝或背压。

订阅由受控句柄表示，事件包含会话、运行/调用或管理操作身份、事件种类及序号；
资源连接/相机帧事件使用对应 ResourceId、FrameId 和后端代次，不伪造节点调用身份。
适配 SDK 回调时只做必要校验、复制/持有和入队，不在回调线程同步渲染、等待本运行或执行加载/保存。
事件进入引擎后仍经提交资格校验，原始回调本身不具有推进控制的权力。
UI 在 GUI 线程消费不可变通知，不依据“画面已刷新”判断算法已完成。

注销关闭该订阅的观察交付。会话关闭时停止新订阅，必要完成路径保留至相关操作实际退出。
有底层回调的后端在排空后按协议撤销注册并等待已进入回调退出。
不能仅因为 UnRegister 返回就假设用户指针可以销毁；
身份/代次检查阻止错投递，对象所有权和在途计数防止悬空访问，二者不可互相替代。
若外部回调缺少足以关联执行的身份，适配器须使用已验证的执行计数/序列映射，
或限制该后端对象的在途调用数；仍无法消歧时报告关联错误，不把迟到结果分给“当前运行”。
这类适配限制不改变 VisionPro 原生控制图及多流程能力。

## 9. 诊断

诊断至少包含：

- 稳定错误码。
- 严重程度。
- 可读说明。
- 相关流程、节点、端口或参数位置。

结构错误、参数错误、资源错误和运行错误应可区分。
日志文字不能作为程序判断错误类别的唯一依据。

S2.1–S2.5 的 [diagnostic.hpp](../include/visionpro/core/diagnostic.hpp) 提供
`Diagnostic`、`DiagnosticLocation`、`Severity`、`ErrorCode` 和 `ErrorCategory`。
诊断拥有说明文本和可选的方案/流程/节点身份，不借用调用者的字符串或配置对象；
S2.2 增加工具、Schema、输入、输出、参数身份及字段/元素索引路径，不使用名称字符串替代对象位置。
错误分类由错误码派生，不受可读说明影响：

| 错误码 | 稳定数值 | 分类 | 含义 |
|---|---|---|---|
| InvalidIdFormat | 1001 | Structure | 长度、分隔符或十六进制字符非法 |
| InvalidIdVersion | 1002 | Structure | 非 UUIDv4，包括 nil |
| InvalidIdVariant | 1003 | Structure | variant 不是 `10` |
| IdGenerationFailed | 2001 | Resource | 系统随机源失败 |

新增错误码不重编号现有码；未知枚举值报告 `Unknown` 分类和 `UnknownErrorCode` 名称。
S2.2 增加稳定的身份/Schema/值/元数据错误码：1004–1007 为 token/运行/关联身份错误，
1101–1108 为 Schema、UTF-8、类型、字段和 Enum 错误，1201–1209 为元数据及兼容性错误。
计数耗尽归 `Runtime`，值/约束/来源与转换错误归 `Parameter`，定义及兼容性错误归 `Structure`；
完整映射以公共头文件及 `error_category` 为准，原有 S2.1 错误码数值保持不变。
S2.3 增加图像 1301–1304、几何/坐标/掩膜 1401–1407、资源/路径 1501–1505 和
状态/队列/全局变量 1601–1603 错误码；诊断位置增加资源、变量、队列与区域的强类型身份。
S2.4 增加 1701–1708 的模型、重复身份、包含、绑定、快照、请求、结果及外部复制引用错误，
位置补充 ControlLinkId。局部诊断可以保留方案/流程/节点和具体输入、输出或参数位置。
S2.5 增加 1709–1716：UnknownTool、InvalidControlLink、InvalidSelector、ScopeViolation、
ControlCycle、DependencyCycle、ControlOrderConflict、IncompleteExecutionScope，均归 Structure。
S2.6 增加 1801–1811：结果身份不匹配、重复/退役结果、无效解析上下文、来源失败/取消/超时、
输入不可用、运行索引越界和全局快照缺失/版本不符，均归 Runtime；Pending 是解析结果分支，不是伪造的错误值。
[result.hpp](../include/visionpro/core/result.hpp) 将 `Result<T>` 定义为
`std::variant<T, Diagnostic>`；调用方通过 `std::get_if` 或 `std::holds_alternative` 检查分支，
预期失败不返回伪造的有效 ID，也不要求解析日志。解析尚未取得身份时，诊断位置为空，
调用方可补充已知的外层对象位置。内存分配失败等非预期异常不在值类型内部吞掉，
工作线程与 UI 回调的异常转换仍按 §2 的边界在后续阶段实现。

适配诊断的目标契约是以类型化字段保留 provider、API/模块名、错误域、原始数值码及描述、后端版本和关联身份，
与本项目归一化的 ErrorCode 同时存在；不依赖解析 message 恢复原码，也不以任意键值字典承载这些固定语义。
SDK 调用错误、算法状态、输出有效性、资源连接和业务判定分别归类；
字符串参数接口和名称查找只在适配边界解析/映射，不放宽核心类型、编码和稳定身份要求。
未知厂商错误保留原码并标为未映射，不能默认归为 NG 或可重试错误。
耗时按测量范围分别记录排队/等待、调用墙钟、工具报告模块耗时、工具报告算法耗时、结果物化及显示耗时；
每项包含明确单位、测量来源及已知/未知状态，未测得不能记为零，也不能把多分路耗时直接相加当作流程总时长。
外部报告的模块耗时可能包含算法耗时，不将两者相加；单位须由相应接口契约确认，未知时不得猜测并换算。
SDK 示例中的 fModuleTime/fAlgorithmTime 说明了测量范围，但该示例未明确单位，不构成本项目单位选择的依据。

S3.1 的 `Diagnostic.external` 可选保存 `ExternalDiagnostic`，包含 provider、operation、类型化状态域、
原始数值码、映射状态、可选厂商域、描述及后端版本。归一化的 ErrorCode 和位置字段继续保留。
`ToolCompletion` 与 `NodeResultData` 的 `elapsed` 是可选的原生调用墙钟纳秒，实测零有效。
`timings` 按测量范围、来源、单位、可选数值和提供方保存其他测量。可分别表达未测量和已报告但单位未知。
结果投影保留这些字段，系统 Elapsed 绑定只读取原生墙钟，缺值报告 InputUnavailable。
S3.6 通过模拟适配验证各域的成功码、未知原码和分范围耗时。真实厂商接口及其单位由 S6 的后端验证确认。

## 10. 资源、版本与持久化（C09）

方案保存稳定身份、节点配置、控制/包含关系、绑定、资源定义、变量初值、
队列模式与策略、状态初始化/重置策略及必要布局。
运行缓冲、设备句柄、线程、当前共享值、队列积压、累积状态和临时结果默认不保存；
运行恢复使用独立检查点契约，不改变“保存方案”的含义。

### 10.1 资源种类与读取时机

| 资源 | 配置与运行规则 |
|---|---|
| 方案托管资源 | ResourceId、类别、版本/内容摘要、相对定位；已发布版本不可原地改写 |
| 外部文件 | 路径、显式解析基准、内容校验与读取策略；不强制全部复制进方案 |
| 目录/图像序列 | 文件集合/过滤、排序、切换、重复、缺失/失败和触发策略显式；不能依赖目录枚举偶然顺序 |
| 设备/通信 | 保存逻辑 ResourceId 与配置，解析为受控能力/租约，不序列化 SDK 句柄 |
| 输出路径/命名 | 保存路径基准、文件名绑定、覆盖/容量策略，不自动把运行产物并入方案 |

相对路径声明以方案目录或命名资源根为基准，不依赖进程工作目录；
绝对路径属于明确外部依赖，跨机器无法解析时报告诊断。
模板与标定等固定资源在计划使用时锁定版本；编辑生成新版本，旧版本保留至持有者结束。
锁定须落实为已加载的不可变内容或经校验的版本读取；外部路径内容变化不能混入正在使用的旧版本。
动态输入在采集时读取，记录实际文件/帧来源及必要版本/摘要；同一路径不表示内容不可变。
图像序列的当前游标属于运行状态，普通保存只存策略和初值。

用户可以选择保存引用或将所选文件嵌入/托管。
便携导出必须列明仍存在的外部依赖，不能宣称包含未收集的目录、设备或外部文件。
设备连接归资源服务；实例归还租约不误关共享连接。

### 10.1.1 S2.3 资源定义实现

[resource_reference.hpp](../include/visionpro/core/resource_reference.hpp) 定义身份、类别及可选固定版本引用；
[resource.hpp](../include/visionpro/core/resource.hpp) 定义托管文件、外部文件、目录/显式序列、设备配置和输出策略。
`ResourcePath` 明确方案目录、命名根或绝对基准；Windows 绝对路径须为盘符根路径或完整 UNC，
不接受依赖当前盘符/工作目录的路径。托管路径必须相对方案目录且不能用父级跳转或含糊分量逃逸。
托管文件要求正版本和 SHA-256 摘要；锁定外部文件要求摘要，模板/标定不能按调用动态读取。
序列声明排序、推进、重复、缺失、触发及初始游标；设备只持 adapter 标识与类型化 Record 配置；
输出声明命名、覆盖及容量。`validate_resource_reference(ref, catalog)` 检查目录身份唯一性、类别与版本，
不按名称补配或静默改版本。

当前路径检查为词法校验，不访问文件、不解析符号链接、不验证实际摘要，也不连接设备或创建输出。
目录序列的真实文件集合、命名根存在性、句柄租约和加载后内容锁定由后续 infrastructure 负责。
方案保存/加载及 JSON 编码尚未实现，结构可持久化不等于已有序列化入口。

### 10.2 格式与加载

首个存储后端采用目录加 JSON 清单，配置编码与内存布局分开；
托管资源位于方案目录的资源子目录，清单只引用已完整写入的不可变版本。
打包、单文件和加密是后续存储能力，不改变领域配置，也不承诺兼容参考软件 .sol 格式。

方案格式版本、工具配置版本、Schema 版本及资源版本分别管理。
值采用显式类型编码；Int64 用带类型的十进制字符串避免 JSON 消费端精度损失，
引用使用稳定标识，不能依赖控件序列化。具体 JSON 字段规范在第三阶段往返夹具中固定。

加载分三层检查：文件/格式可读性、领域结构与引用诊断、当前执行器能力与运行资源检查。
执行能力校验限定于所选流程及其依赖闭包，其他未选择流程的诊断不自动阻断合法运行；
方案级身份唯一性等全局不变量仍须整体检查，不能通过缩小执行范围绕过。
已知格式中缺工具、缺资源、尚未完成连线或存在暂不支持结构的方案，
应可作为带诊断的编辑模型打开；“可编辑”不等于“可执行”。
未知节点/字段/版本仅在能够无损保留时允许往返；不能无损写回时禁用覆盖保存并说明原因。
未知内容只能作为不解释的兼容载荷保留，不能借此绕过已知核心模型或运行值的强类型校验。
损坏或无法可靠解码的文件加载失败，不替换当前有效方案。
兼容性诊断不能借“降级”静默删除内容；迁移须显式处理版本与结果。

### 10.3 流程/Group 导入导出

复用子图导出包含端口 Schema、控制/包含关系、配置、版本及资源依赖清单，
明确哪些资源随包携带、哪些全局服务须由目标宿主注入；不携带当前状态和结果。
作为新实例导入时分配新身份并重映射内部引用，校验公开端口及外部依赖；
无法解析的依赖保留诊断，不按显示名称误连目标方案中的同名对象。
独立执行的 Group 使用自己的宿主/会话边界；不以“独立”隐含可访问当前方案。
流程/Group 导入导出属于第六阶段能力，使用 VisionPro 自有格式，不承诺 .prc/.gro 兼容。

### 10.4 保存事务

先验证待保存模型的可编码/可保留性，再写入新托管资源版本，
然后在同一目标文件系统写临时清单并通过后端支持的原子替换提交。
提交前失败保留原有效清单及其资源；旧资源不能提前删除。
后端不能保证该提交行为时，应拒绝该保存方式或提供已验证的恢复协议。

清单提交是成功边界；提交后的无用资源清理失败单独报告，不能误报成方案未保存。
打开时记录文件修订/摘要，修订比较与提交必须处于同一受控协议中；
后端使用条件提交或覆盖比较到替换窗口的可靠互斥，不能只检查一次再无条件覆盖。
并发保存者遵守同一协议；无法协调的第三方写入只能按后端实际能力检测，不能宣称原子防冲突。
不能提供所需保证时不直接覆盖该目标，保留编辑内容并支持另存为；检测到冲突时明确报告。
保存方案不改写外部资源；“嵌入”产生托管副本。
故障注入应覆盖资源写入、临时清单、提交及提交后清理，并验证两个保存者交错提交，见 C09 验收。

## 11. 全局变量

全局范围限定为一个方案会话，不作为进程内任意共享字典。

| 对象 | 必要内容 |
|---|---|
| GlobalVariableDefinition | variableId、名称、类型、initialValue |
| GlobalVariableEntry | currentValue、revision、updateOrigin |

读取不消费当前值，写入更新值并推进版本。
updateOrigin 用于追溯流程调用或外部更新来源，不代替业务关联标识。
需定义原子读写、初始化、重置，以及多个变量的一致读取策略。
读写工具将共享服务与普通节点输出衔接，写入是显式副作用。

线程安全或一致快照不保证不同变量来自同一工件。
需配对的数据应包含关联标识，或通过显式同步及消息汇合处理。
例如宽度属于工件 102、高度仍属于工件 101，两个有效值不能直接组合。

目标允许元数据声明的只读 GlobalReference，读取须记录版本与时机；
多变量一致读取须显式请求服务快照，不把各次独立读取误称为原子快照。
第二/三阶段先校验定义，第六阶段实现服务及批量一致性；写入始终为显式操作。

S2.3 的 [state.hpp](../include/visionpro/core/state.hpp) 已分离 `GlobalVariableDefinition` 的 `ConfigValue` 初值
与 `GlobalVariableEntry` 的 `DataValue` 当前值，检查名称、身份唯一性、初值/当前值的精确类型。
更新来源区分会话内调用与明确的外部来源；版本 0 表示初始化。当前没有共享变量服务或写入接口。

## 12. 数据队列

队列是方案会话内有界的 FIFO 消息通道，成功接收后消费消息。
普通字段取值和参数预览不能隐式出队。

| 对象 | 必要内容 |
|---|---|
| DataQueueDefinition | queueId、messageSchema、capacity、overflowPolicy、接收策略 |
| QueueMessage | messageId、sequence、correlationId、producerOrigin、createdAt、payload |

payload 为类型明确的完整记录，例如工件标识、宽度、高度和判定。
sequence 表示队列内成功入队顺序，不保证不同生产者的业务先后顺序。
correlationId 用于标识同一工件或批次，不能直接用不同流程各自的运行标识替代。
messageId 用于辨认重复投递，sequence 用于队列顺序，两者不互相替代。
producerOrigin 区分会话内的流程运行/调用与显式外部来源（会话、来源标识）；
createdAt 用于追溯和过期策略，不作为工件配对依据。
完整记录原子入队，不向消费者暴露未填完的消息。

手册描述 FIFO 和所需行数据齐备后接收，未公开其底层存储实现。
VisionPro 建议区分：

- 单个生产者已提供完整记录：直接入队。
- 多个生产者分别提供字段：按关联标识暂存，齐备后形成完整记录入队。
- 组合读取多个队列：定义齐备条件及全有或全无的消费规则，避免部分出队。

多来源汇合需定义重复字段、缺失、超时及不匹配标识的处理；
尚未齐备的暂存数据也需限制容量和生命周期。
FIFO 本身不能保证跨流程数据正确配对。
汇合键还需包含业务定义的关联范围，避免不同批次复用编号后混合。
参与来源集合、重复/迟到消息与汇合结束后的保留期限必须明确；
CorrelationJoiner 是数据服务，与同一流程内等待控制路径的 Join 无关。

实现前确定空队列、满队列、读取批量、等待取消和多消费者规则。
等待、拒绝写入或丢弃旧消息属于不同策略，不默认选择。
普通消费队列不等同于广播；多个消费者是否分流或各自收到副本需另行定义。
发送或接收失败后如何重试必须明确，不能假定已消费或已发送的消息自动回滚。

S2.3 的 `DataQueueDefinition` 要求完整 Record Schema、正容量、显式溢出/空队列/批量/消费者策略；
最大批量不得超过容量。`QueueMessage` 使用独立的运行期 UUID `MessageId`、从 1 开始的序号、
`CorrelationId`、生产来源、时间及完整 `DataValue` 记录。定义和消息类型/身份的局部校验已实现，
没有入队/消费/等待 API，也未验证 FIFO 调度、重复投递去重或多来源齐备汇合。

## 13. 工具状态、脚本与逻辑

NodeState 与普通输出、全局变量及队列消息分别存储。
运行记录包含节点标识、状态代次、状态作用域、初始化状态与工具内部状态；
重置策略由对应的状态定义声明。

| 数据 | 读取和保留语义 |
|---|---|
| NodeResult | 一次调用产生的只读结果，供本次上下文订阅 |
| GlobalVariableEntry | 方案会话内的共享当前值，写入可覆盖 |
| QueueMessage | 按策略排列并消费的消息 |
| NodeState | 工具内部累积或初始化状态，按声明重置 |

Invocation 状态域在逻辑调用结束时关闭；WorkflowRun 状态每轮初始化；SolutionSession 状态跨轮保留。
各类状态域关闭后均不再授予新访问，既有操作持有的状态对象及访问权保留至实际退出，不能在取消时提前销毁。
累加器可每轮从初值重置，或跨轮累积到显式重置/会话结束；脚本 Init 在所属状态域初始化一次。
同节点的并发状态访问由串行化、隔离副本或工具明确支持的并发策略控制，不能仅用进程静态变量维护。
实例更换不等于状态重置，配置兼容性与状态代次按 §2.1 管理。
工具须声明状态修改发生在计算中还是结果接受时；取消、失败及重试不保证自动回滚状态。
持久化保存节点选定的初值和重置等配置及其工具版本约束，默认不保存当前累积值或 Init 进度；
有效状态规格由所加载的类型化配置重新生成，不能只保存工具级默认值而丢失节点选择。
初值、寿命域或重置选择改变时，按工具声明检查兼容性并决定是否建立新代次；
需要应用新初值的变更不能默默继承旧累计值，也不能提前重置在途快照使用的旧代次。
显式重置以受控操作作用于选定节点及状态域，不通过修改共享 ToolDescriptor 影响同类型的其他节点。

S2.3 已实现 `NodeStateDefinition` 的 Schema、配置初值、寿命域、重置、兼容、修改时机及并发策略，
`NodeStateKey` 用节点、正代次和显式 Invocation/WorkflowRun/SolutionSession 域区分运行状态。
`NodeState` 的初始化状态与当前值/失败诊断一致性可校验；Ready 必须有同类型值且无错误，
其他阶段不能发布当前值，Failed 必须携带错误诊断。调用域还检查键中节点与调用节点一致。
当前 `IsolatedPerInvocation` 仅适用于 Invocation 寿命域，跨调用保留状态须声明 Serialized 或 ToolManaged；
此检查只约束策略一致性，不实现锁或并发调度。
`next_state_generation` 拒绝零和溢出，不因执行实例更换自动修改代次。
S2.3 的验证覆盖定义和运行记录校验，实际 Init、重置与访问权由 S3.5 接入。
S3.1 通过 `ToolDescriptor.state_parameters` 将状态初值映射到同类型的 SnapshotBuild 参数，
将寿命域和重置策略映射到 SnapshotBuild Enum 的可选成员。工具元数据校验每个可选成员都有唯一合法的策略。
`ToolExecutionConfiguration::effective_state()` 固定本节点选择，未映射的字段沿用类型级状态定义。
同一工具类型可配置不同初值和每轮/会话策略。节点绑定保存可编辑选择，S3.7 验证选择往返。

脚本与逻辑工具复用 ToolDescriptor 和 Binding：
已解析输入进入工具，输出经类型校验后作为普通节点结果发布。
脚本输出定义应可检查，不允许通过任意键写入其他节点的内部结果。
全局写入和队列发送通过受控接口显式执行，不暴露原始容器或 GUI 对象。
脚本语言、执行后端和复杂表达式引擎暂不选定。

算术、比较和格式化产生数据；分支选择控制出口；循环管理执行作用域。
是否继续执行是控制策略，不能仅凭结果值更新自动触发。

### 13.1 S3.5 状态访问与代次

状态仓库按引擎会话、流程和节点持有当前代次。Invocation 域随调用建立，WorkflowRun 域随运行建立，
SolutionSession 域在兼容配置的多次调用间保留值。兼容配置可保留代次，新的调用或运行仍使用自己的域身份。
`ToolInstance::initialize_state` 从已物化的配置初值生成本域的首次状态。Init 成功后使用该值，失败诊断保留在该域。
按调用创建的新实例可复用已初始化的会话状态。

PreserveCompatible 在工具及 Schema 版本、有效状态规格一致时保留代次。
AlwaysNewGeneration 还比较固定参数、资源槽及节点绑定。改名、布局和请求输入变化不参与兼容比较。
不兼容的配置首次用于活动调用时分配新代次。旧操作依其固定上下文持有状态至实际退出。
Isolated 调试使用单独代次，不变更活动代次的选择。

`ToolStateAccess` 绑定完整调用与尝试身份，提供 `read` 和精确类型的 `write`。
单次读写由访问接口串行化，复合读改写由工具协调。
DuringComputation 在计算中写入当前值，已经发生的写入在失败或取消时保留。
OnResultAccepted 在调用内暂存，工具可读到自己的暂存值，执行器接受成功结果时一并提交。
失败、无效结果或失去提交资格均丢弃暂存。有效逻辑完成或提交资格撤销时封存写入，读取持续到后端对象清理，随后撤销访问。

## 14. 契约审查与可复现验收（C10）

手册依据、设计理由、场景编号及实现阶段集中在 [requirements.md](requirements.md) §2、§9，
可复现记录和验证方法见 [development.md](development.md)。
每个 C01–C10 至少有正常、边界或失败场景，设计审查和实现验证分别记录。

必须检查以下跨契约关系：

- 五路测量/条件判断汇合后，逻辑与发送各调用一次；数据来源不靠控制线隐式传递。
- 按位分支选择多路、零选及嵌套关闭传播；失败不能伪装成 NotSelected。
- 同一扇出下的数据依赖可细化就绪顺序，显式逆序依赖仍报错。
- 同类型节点状态隔离；实例替换、配置编辑与状态重置不混为一件事。
- 动态索引、普通越界错误和格式化声明的容错行为分别验证。
- 共享/裁剪图像在取消和历史淘汰后仍有有效持有者；ROI 修正不偷偷退化成矩形。
- 重复完成、取消竞争和旧尝试迟到不产生第二次发布或发送。
- 普通结果、共享当前值、消费消息及跨工件汇合身份分离。
- 托管/外部资源可往返；缺失依赖可诊断编辑；保存中断不破坏旧清单。

上述场景定义不表示对应执行器、算法或设备已实现。
不得用编译成功代替功能验收，或用模拟网络成功代替真实协议验证。
