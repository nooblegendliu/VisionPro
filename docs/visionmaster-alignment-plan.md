# VisionPro 框架与流程设计修复方案

本方案的目标是**让一份方案中的多个流程能按公开契约协同运行，并且每次传值、分支、停止和外部触发都可复查。** 先用已有流程在无界面引擎中跑通，再接入桌面编辑和调试。具体算法节点、参数细节和数值兼容移交后续节点专项。

设计基线为 [S6.12 验收](s6-acceptance.md)，对照用户提供的《VisionMaster 算法开发平台用户手册 4.4.3 Lite》（2026-05-15）。下文使用印刷页，PDF 阅读器页码加 14。文中的调度、版本和并发规则属于 VisionPro 的设计。

2026-11-23 首轮交付覆盖 F1–F3。v2 磁盘样例可通过 `run-solution` 提交一次，报告含公开输出、具体子运行、跨流程交付和控制边的关闭原因。第 2 节记录实施前的差距，F4、F5 及完整方案画布属于后续范围。[可运行样例](../samples/f3-solution-graph/solution.json) · [命令与输入](development.md#1-当前阶段)

本次 Windows x64 Release 验收通过。无界面配置通过 133/133 项，Qt Widgets 与 OpenCV 配置通过 176/176 项。桌面回归使用 Qt 离屏平台，两种配置均关闭 MVS。整方案的运行、取消及报告查看已接入“运行”菜单。专项回归为 `app.cli_solution_graph`、`workflow.solution_rounds`、`workflow.state_session_publication`、`infrastructure.solution_roundtrip` 和 `visionpro_editor_run_tests`。

## 1. 第一个里程碑

**在同一个方案里连起两条已有流程，将 A 的公开输出 `area` 映射到 B 的公开输入 `fifth`。** 用户只启动一次方案。引擎执行 A，提交它本轮的公开结果，再按映射构造 B 的输入。CLI 和桌面都能回答“B 为什么执行、用的是哪个 A 的结果、哪个后继被跳过”。

仓库的[计算与条件分流样例](../samples/s6-calculation/solution.json)已具备两端。A 的默认列表是 `[6,9]`，B 的第五路判断范围是闭区间 `[0,8]`，其输入默认值为 9。在当前 Release CLI 中分别运行 A 和 B，已经得到以下单流程基准。实施时从样例选择前两条流程，设 A 为方案入口，B 只经 A 启动。

| A 的输入 | 已核实的单流程行为 | 新框架的验收断言 |
|---|---|---|
| `index=0` | A 映射的源节点输出 6。给 B 传 6，仅执行“合格后继”。 | B 自动收到 6，只启动一次。来源能追溯到本次 A。这一例能检出映射失效后 B 误用默认值 9。 |
| `index=1` | A 映射的源节点输出 9。给 B 传 9，流程技术成功，仅执行“不合格后继”。 | F3 验收默认继续策略。F4 再开启遇 NG 停止，第五路判断保留有效的 `passed=false`，其后继均未启动。B 的公开 `passed` 来自后面的“五路逻辑与”，本轮应报告未产出。 |
| `index=2` | A 以 `IndexOutOfRange` 失败。 | 在一轮成功运行之后再输入 2，B 的启动次数为零，既不使用前轮结果，也不使用本地默认值。 |

完成标准是**重新打开磁盘方案后，运行一次方案即可复现表中结果**。单独运行 B 仍可显式提供 `fifth` 进行调试。[既有 CLI 入口](../source/app/main.cpp) · [现有单流程回归](../tests/app/cli_tests.cpp)

## 3. 方案模型和执行契约

### 编排与数据传递

手册第 79、139–148、152–156 页区分整方案与单流程运行，并描述后序流程订阅前序流程的公开输出。VisionPro 在 `Solution` 层增加显式入口、流程间执行连接、公开端口映射及独立布局。首批覆盖无环方案编排，循环继续使用已有结构化作用域。

- **控制、数据和包含分别编辑。** 执行连接决定目标是否得到启动许可。数据映射只引用“源流程 ID＋公开输出 ID”和“目标流程 ID＋公开输入 ID”。Group 内部结果通过 Group 公开口导出，画布位置及名称只参与显示。新增绑定不激活生产者。
- **编译前校验。** 检查入口和可达范围、控制环、数据依赖环、逆序或越域引用、类型和单位，以及同一输入多次供值。停用或未选中的路径应能关闭。如果合法分支可能让必需输入缺失，要求显式处理缺值或给出诊断。已配置映射却取不到值时，不能转而使用未配置输入的默认值。
- **同轮交付。** 根流程结束时，从本次作用域投影公开数据和命名控制出口。每个公开数据口带类型、值或缺值原因，已产出的值关联到原节点、端口、作用域、调用和尝试。绑定记录同时保留源流程轮次和目标流程轮次。句柄按需求持有结果及图像所有权，UI 淘汰历史不能使在途消费者失去数据。
- **分支与汇合。** 单个方案轮次内，每条控制入边有等待、到达、关闭及关闭原因。未选分支向下传播关闭。普通汇合沿用 `AllActivated`。等相关入边均已确定，至少有一路有效到达，且必需数据齐备时，目标只启动一次。全部正常关闭则跳过，未处理失败进入失败路径。多个独立轮次按工件号配对时继续使用显式业务汇合。[现有分叉与汇合契约](data-model.md) · [分路用例](../tests/workflow/workflow_fork_join_tests.cpp)

### 方案轮次与会话生命周期

在 `workflow` 层增加方案运行协调职责。它持有本轮方案身份、配置快照、资源提供方、共享状态代次，以及已受理的子流程句柄。现有 `WorkflowEngine` 继续执行节点和 Group，`infrastructure` 管理文件、通信和设备，`ui` 与 `app` 只提交命令和读取结果。

| 时点 | 建议契约 |
|---|---|
| 受理 | 先校验整方案的静态编排，固定方案输入、快照和资源。方案轮次 ID、流程运行 ID、节点调用 ID、工件关联键分别记录。整方案连续运行每次产生独立轮次，沿用配置的准入与背压。 |
| 前驱完成 | 先提交公开结果，再通过引擎内可靠的完成通知推进后继。相同完成记录重复到达时只派发一次。面向 UI 的有界观察通道允许丢通知，消费者可按身份重查。[观察接口](../include/visionpro/workflow/run_observation.hpp) |
| 子流程准入 | 普通 A→B 交付复用 B 的在途与等待容量。若当前策略返回 Busy 或 Reject，在方案轮次记录目标和原因。首版默认把未处理的拒绝报告给调用方，单次方案不会后台无限重投。选择“首个空闲流程”的事件采用第 5 节的即时准入。 |
| 运行中发布配置 | 当前会话会在准备及最终准入时核对活动快照。为已受理方案提供内部子提交路径，仅允许该方案句柄使用自己持有的快照、资源和状态代次。A 执行期间发布新配置后，旧轮 B 继续用旧修订，新开一轮使用新修订。普通外部旧请求仍按原规则拒绝。 |
| 停止与切换 | 停止连续触发时先封闭新事件。选择排空时，已受理方案轮次可完成其合法后继。选择取消时，关闭待派发后继，向已启动子流程发协作取消。换方案先验证候选，再按选定方式收尾旧会话，失败保留有效方案。用会话和轮次身份拒绝迟到回调。 |
| 完成与释放 | 业务终态对外可查询。每个流程的准入名额保留至该流程实际退出，设备租约等最后一个使用者退出后释放，队列预约按第 5 节的消费或撤销规则结算。关闭窗口在后台等待。UI 和 CLI 区分逻辑完成、正在清理、已退出，并可查具体子流程。[会话接口](../include/visionpro/workflow/workflow_session.hpp) · [生命周期测试](../tests/workflow/workflow_session_tests.cpp) |

**整方案如何收尾。** 全部计划路径均完成或正常关闭后，才产生方案逻辑终态。首版遇到未处理的技术失败时关闭尚未派发的路径，保留失败位置和已启动子流程的最终记录。正常未选路径可以使方案成功结束。业务 NG 单独汇总，主动取消、超时和失败各自记录原因。重复通知或迟到回调不能覆盖已提交的终态。整体释放另以所有子流程均已清理为准。

## 4. 流程策略、状态与作用域

**NG、失败和超时。** 手册第 150–151 页允许流程遇 NG 停止，也允许为整条流程设时限。框架消费节点已有的技术状态、业务判定和诊断，不要求节点增设专用端口。建议按以下次序处理最终调用结果。

1. 提交该调用的有效输出和判定。技术成功且业务 NG 时保留数据，旧方案默认沿普通控制线继续。开启遇 NG 停止时，记录触发停止的节点、轮次和原因，关闭该流程尚未派发的后继。已派发兄弟调用收尾，已产生的外部效果按操作身份保留。方案默认记录该流程的业务停止并关闭其普通后继，可通过显式处理分支继续其他路径。
2. 整流程时限从实际开始执行计时，排队时间单列。到期时关闭新派发，让在途调用收尾，再报告流程超时。单节点尝试期限、句柄等待截止时间、整流程时限分别记录。重试、回调和取消在同一仲裁点只能提交一个最终决定，节点级错误出口和原始诊断仍可查询。
3. Group 与循环保留自己的调用、迭代和结果边界。手册第 1172–1173 页给出 Group 公开输出、累积输出和状态的约定。为界面/订阅提供单独的兼容状态投影。例如未配置公开输出、内部调用均成功时，海康显示模块状态 0。该字段与引擎技术失败分别表达，是否参与遇 NG 停止由明确的判定设置决定。零次循环、提前中断和未产出均保留原因。

**变量与结果写入。** 按手册第 162–165 页，为变量定义补充稳定所有者和可见范围。方案变量可跨流程访问，流程局部变量仅对本流程直接作用域可见，Group 局部变量仅对本 Group 直接作用域可见。增加“最终有效输出写入指定变量”的显式映射，静态校验目标可见性和类型。通过最终提交仲裁写一次，再放行后继。普通订阅保留本轮快照读取语义，显式当前值读取在调用时记录修订号。隔离调试使用私有状态。

建议首版为局部变量明示“按流程轮次／Group 调用隔离”的寿命，两个在途工件并排验收。海康重入时的局部值寿命列为对照项。跨轮共享由显式配置决定。热发布时，把所有者和寿命加入兼容性检查，改名可沿用兼容单元，变量移到另一个 Group 时新旧运行各用各自的状态代次。常规保存只保存定义和初值，若提供“保存变量”，由显式操作选定运行值写入配置。[共享模型](../include/visionpro/core/shared_data.hpp) · [热发布与隔离测试](../tests/workflow/workflow_state_tests.cpp)

**给后续节点的接入契约。** 静态工具描述符声明输入输出、可订阅参数、状态、资源和副作用，调用实例取得本次快照。最终结果按端口表达有效值、有效空集合或未产出，同时发布技术状态、业务判定、诊断和选中的控制出口。框架据此决定可否试算、重试和推进后继。结果面板先按类型和来源提供通用展示，专用渲染器单独注册。扩充工具目录时即可复用这套契约。[工具描述符](../include/visionpro/core/tool_descriptor.hpp) · [工具调用](../include/visionpro/core/tool_execution.hpp) · [现有注册](../source/app/tool_catalog.cpp)

## 5. 触发与多流程分派

方案层保存事件源、候选流程顺序、触发条件和全忙策略。设备适配层产生带会话及流身份的事件，运行时决定谁执行。首批使用已有外部事件、共享队列和模拟相机。

| 来源 | 准入与交付规则 | 可复现的验收 |
|---|---|---|
| 手动／连续／通信事件 | 统一为带来源、目标和固定输入的请求。通信可映射启动流程、调用已声明动作或切换方案等宿主命令。停用流程后拒绝对它的新触发。终止旧方案时封闭入口并记录迟到事件。手册第 143、165–167 页。 | 用可控事件序列验证单次、连续、停止、禁用和切换。对旧会话补发事件，新会话的启动次数不增加。 |
| 全局相机 | 每个物理设备持一个采集租约，将每帧交给顺序首个可立即运行的流程。在最终准入临界区选择目标，保留既有 FIFO 次序。等待队列有容量或前轮正清理时均不算目标空闲。所有目标都忙时按显式策略记录帧处置。手册第 1214–1215 页。 | 用门闩控制 A、B 的忙闲，逐帧核对唯一受理者。关闭 A 后 B 继续收帧，最后一名订阅者退出后设备可重开。[现有相机夹具](../tests/app/camera_stream_tests.cpp) |
| 多列数据队列 | 各列齐备后预约整组消息，再按候选顺序尝试即时准入。预约和名额最终共同生效，绑定消息 ID 与获准的运行 ID。读取前受理失败、取消或运行绕开接收时结算预约。成功接收后即使超时也只消费一次。满队列丢旧策略需识别预约项。同步全忙按配置弃/留，异步可再次尝试，主动停止单独记录。手册第 197–201 页。 | A 能排队但不能立即运行时改派 B。并发消费者不能抢走预约消息。分别在接收前后取消，核对剩余消息、消费数、丢弃数和原因。[队列夹具](../tests/workflow/shared_data_tests.cpp) · [在途与等待测试](../tests/workflow/concurrency_tests.cpp) |

候选流程忙时可继续尝试下一项。会话失效、配置失效或来源错误时结束本次分派并报告原因。相机、队列、通信适配器沿用既有抽象，后续设备和协议可通过同一事件入口接入。

## 6. 编辑、调试和持久化

**从画布到运行。** 桌面增加“方案 → 流程 → Group”导航。方案画布编辑流程、事件源和队列路由，流程画布编辑控制关系，属性区独立编辑输入和公开端口映射。增加连接、重命名、移动、复制和删除都使用现有草稿与撤销机制。删除带引用的对象时列出受影响的端口及消费者，修改不完整的草稿可定位诊断。GUI 与 CLI 复用同一个校验器、方案提交入口和结果接口。[画布模型](../source/ui/control_graph_model.cpp) · [属性检查器](../source/ui/editor_inspector.cpp)

桌面运行采用“编辑草稿 → 校验目标范围 → 受理并发布快照 → 观察该轮”的顺序。保存到磁盘是独立命令。受理失败时展示草稿中的错误并保留现有活动快照。已发布的方案继续编辑时，历史结果保留当时的绑定和修订。单独运行当前流程只校验其所需范围，从界面进入 Group 查看也不会隐式启动它。

**命令与追溯。** 区分运行/连续运行整方案、运行当前流程、调试所选节点或 Group。仅在有明确目标时启用相应停止命令。CLI 拟增 `run-solution`，保留现有 `run --workflow`、`trigger` 和 `replay`。调试使用显式输入、快照及隔离状态。结果页按方案轮次展开流程、调用、尝试和绑定来源，同时展示“未选分支”“上游失败”“因 NG 停止”“目标忙”等原因。历史画面标明原始轮次，显示缓存只服务于回看。GUI 合并刷新不影响实际调度。[桌面运行](../source/ui/editor_runs.cpp) · [CLI 摘要](../source/app/run_summary.cpp)

**格式与迁移。** 建议新增 v2 以保存方案图、路由、局部所有者及流程策略。读取 v1 时采用原有行为，旧单流程及批量入口保持可用。用户开始配置方案级关系时显式选择入口，不能仅按流程排列顺序推断连接。仅使用 v1 能力时可按 v1 保存，使用 v2 专有字段时提示升级并支持另存。加载、校验、运行、保存、另存和导入使用一致的版本判断。未知字段遵守现有禁止有损覆盖的规则，失败保存保留原文件。[方案加载](../source/infrastructure/solution_file.cpp) · [事务保存](../source/infrastructure/solution_save.cpp)

整方案复制时重映射流程、连接、变量所有者、结果写入目标和触发目标。单流程或 Group 导出时列出外部依赖，导入方显式重绑或收到诊断。布局独立保存。活动轮次、变量当前值、排队消息和设备句柄属于运行期。保留 v1 原样、v1 升级副本、v2 重载、未知内容和保存故障五组往返用例。[复制](../source/workflow/copy.cpp) · [导入导出](../source/infrastructure/solution_transfer.cpp) · [既有保存回归](../tests/infrastructure/solution_save_tests.cpp)

## 7. 工作包与完成条件

| 顺序与依赖 | 代码交付 | 可签收的结果 |
|---|---|---|
| F1 根流程公开结果 | 将现有公开输出映射应用于根流程，为句柄和单流程 CLI 增加结果与来源。 | 用现有 A 查得 `area=6/9`，可定位源调用。失败轮无有效值，旧单流程调用继续工作。 |
| F2 方案图与格式，可与 F1 并行 | 实现入口、控制连接、端口映射、作用域校验及 v1/v2 往返，覆盖复制、悬空引用和未知字段。 | A→B 方案可保存重载。反向依赖、越界和重复供值在运行前报告到具体端口。 |
| F3 方案运行，依赖 F1、F2 | 在会话内受理方案，可靠推进子流程，接入 CLI、取消与热发布。 | 第 1 节的 6、9、越界三例在一次方案提交下成立。中途发布配置仍按原轮次完成，重复完成通知不会重复启动 B。 |
| F4 流程策略与状态，整体验收依赖 F3 | 实现 NG 停止、整流程期限、Group 状态投影、局部变量和最终结果写入。 | 对同一 NG 对比开关前后的派发列表。验证排空/取消、并行收尾、局部变量跨调用隔离以及热发布后旧写不污染新代。 |
| F5 事件与分派，依赖 F3 | 即时准入、队列预约与结算、多流程相机投递、宿主事件动作及关闭顺序。 | 用相同事件序列重放 A 忙、B 空闲、全部忙、接收前后取消和旧回调，逐条核对交付对象与次数。 |
| F6 桌面及综合验收，随 F2–F5 分批接入 | 方案画布、端口编辑、运行命令、历史和诊断。更新需求、数据模型、架构及开发文档中的已实现范围。 | 从桌面新建或编辑 A→B、撤销并恢复接线、保存关闭，独立 CLI 加载同一文件。按工件比较运行结果、后继、来源和停止原因。 |

**首轮验收截点为 F3。** F1–F3 全部可以用现有整数运算、判断与分支工具验收，无需相机、PLC 或新算法。F4/F5 复用并发门闩、可控时钟、共享数据和模拟设备夹具。综合验收另覆盖分支零选/多选、Group/循环、观察队列溢出、停止期间的迟到完成和全部资源退出。容量与 GUI 响应沿用[既有性能基线](s6-acceptance.md)。

**后续交接。** 框架验收完成后，算法与工业节点另行排期。它们接入既有描述符、类型化端口、运行结果、状态和资源接口。海康对重入局部变量寿命、并发 NG/超时收尾、设备全忙时帧处置的细节仍需客户端或实物验证，分别记录在对应策略下。
